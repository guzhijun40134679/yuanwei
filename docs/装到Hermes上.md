# 装到 Hermes 上（预览版）

给用户看的一页：怎么装、怎么用、怎么看状态、怎么卸掉；每一步会改什么、怎么撤回。写的是预览版现状，2026-11-11 在 Hermes v0.22.0（+10397）上试装过，记录里列的各项都过了；没覆盖到的写在最后的限制里。0.1.0a10 又在隔离的 Hermes v0.23.2 上用假模型、断网回归过（约 180 个场景，走桌面版用的网关和 Hermes 的微信接口；和 0.1.0a9 共有的 175 个场景逐个比，没有一处退步），并在作者的一台 Mac 上用桌面版日用了一天（第二天又在微信上补测了两句），没丢轮；Telegram、Discord、Slack 等别的聊天平台没在真机上试过。装到你自己的 Hermes 上之前，会先问你。

## 先说五件事

1. **工作区只有两种：项目和「生活」。** 你在某个 Hermes 项目的文件夹里聊天，就记进那个项目；不在任何项目里的对话，都记进「生活」。Hermes 的机器人（配置档案，profile）每个有自己的记忆库，互不相干——但**新建的机器人要单独装一次**，见下面第 5 条。
   认不出这次对话属于哪个项目（**给了**当前目录但不合格、项目已经归档、项目表读不了）时，**这一轮不记也不查，不会偷偷记进「生活」**。
   **宿主没给当前目录**时（Hermes 的经典终端、新终端界面、桌面版聊天窗口建对话时都不传）：经典终端取 Hermes 进程此刻的工作目录来判项目；本机的桌面版、新终端界面（平台 `desktop`、`tui`、`local`）**问 Hermes「这一轮的文件夹」**来判项目（只管这几个本机入口；Telegram 等网关聊天平台不问，没传目录就照旧记进「生活」）——桌面版的对话走 Hermes 网关自己的会话管理，那条路建助手时不传目录（Hermes 上游问题 #144869），但这一轮进行时 Hermes 自己知道文件夹，原委用它的内部函数（`agent.runtime_cwd.scoped_session_cwd()`，取不到再取 `gateway.session_policy.active_policy().cwd`）取到。规矩：只在主对话里问；**绝不用进程目录**（网关是长期运行的进程，用它会把所有项目钉成同一个）；取到的值要展开 `~`、是绝对路径、本机上真有这个目录，否则当没取到；`~`（家目录）也按项目表判断，没有项目覆盖它时才归「生活」。这用的是 Hermes 的内部函数，不是写进插件接口的约定：Hermes 把两个都改名、或者都问不到（不在这一轮里），才退回记进「生活」（只剩一个来源时仍可能取到），插件照常工作；等 Hermes 上游修好 #144869，原委就直接用它传来的目录。取到、但不能用的值只记个数（`status` 里的 `host_cwd_dropped`），不记路径。宿主没给目录、后备也没取得有效目录时（取不到、是根目录 `/`、不是绝对路径），落进「生活」。给了目录的，判法不变。`yuanwei doctor hermes` 会核这两个内部函数还在不在：有任意一个就算正常（会写明哪个在、哪个不在；这只说明至少还有一个候选接口在，实际能不能取到值、作用域对不对，要另外核），两个都没有才报「变了」（桌面版会退回记进「生活」，不是致命错误）。`yuanwei status hermes` 里 `workspace.reason` 写着依据：`cwd_given`（宿主给了）、`cwd_from_process`（取了进程目录）、`cwd_from_host_turn`（问 Hermes 这一轮的文件夹取到的）、`no_cwd_life`（没目录，记进生活）。**这次没做：** 对话中途换项目文件夹时不再取一次（会话被挪进别的项目时 Hermes 会重建助手、原委重新初始化，走的是同一段代码）；本次验证针对普通桌面主对话；整理用的会话、`/btw`、`/bg` 这类旁支和辅助会话不在这一轮的范围里，不承诺统一落入「生活」。其中 `/btw` 的分支，Hermes 自己设了 `skip_memory=True`，原委不记，这是 Hermes 本来的设计。
   **恢复会话：** 启动时 `hermes --resume` 是 Hermes 先切到那个会话记的目录再启动插件，所以和新对话一样判；会话中 `/resume`，经典终端在下一轮开始时按进程目录重判一次（Hermes 在通知插件之后才切目录），宿主在通知里带了 `cwd` 就直接用；新终端界面、桌面版没目录就先问 Hermes 这一轮的文件夹，问不到才记进「生活」；压缩、分叉、新对话、撤销一概不重判。聊天平台恢复会话照旧说不清。
   **注意：读取范围选「甲」（每个工作区只翻自己）时，宿主没给目录、后备也没取得有效目录的项目对话会落进「生活」，只翻得到「生活」里的话。**
2. **能翻哪些工作区（读取范围）默认是「乙」：在「生活」里能翻生活和所有项目，在项目里只翻这个项目自己。** 写入永远只写你当前所在的工作区。想要更严或更松，装的时候选：
   `--read-scope isolated`（甲：每个工作区只翻自己）、`--read-scope life_all`（乙，默认）、`--read-scope all_open`（丙：全部互通）。这个范围只听你的设置，模型在工具参数里写什么范围都不算。
   一次翻了好几个工作区时，每一段材料前都标明出自哪个项目或「生活」，开头一行写读取范围。`recall` 先合并各区按名次选好的材料，再分页；有下一页就给续读游标，不把放不进第一页的工作区悄悄丢掉。真正读取失败会明确报错。
3. **只记你本人的话。** 本机终端里说的话就是你的。（新终端界面和桌面版如果带着登录身份——经 WS 登录的网页后台或桌面版，Hermes 把登录的 `user_id` 传进来——原委在 Hermes 进程里用 `gateway.owner_identity.host_owner_subject()` 取这台电脑主人的系统身份来比：**相等就是主人**，不用配（`status` 里依据写 `host_owner_login`）；不相等，和聊天平台一样要配 `--owner tui:账号`／`--owner desktop:账号`，没配不记（跳过原因 `login_identity_needs_owner`），配了对不上是 `not_owner`；这一版 Hermes 没有这个函数、或调用失败，就**没法验证**，不当主人（`login_identity_unverifiable`），这时只能先用不带登录身份的入口（经典终端），或等原委跟进。比较只在内存里做，身份的值不写进库、不打印。没带登录身份的入口不受影响。）从手机、聊天软件（Telegram 等）进来的，要你先告诉原委哪个账号是你：装的时候加 `--owner telegram:你的账号编号`（可以写多个）。
   **没有登记的平台，聊天软件里的话一条都不会记，也不会让模型去翻记忆。** 向导会对检测到的平台逐个问本人编号，可跳过；已经装好的可以用下面的 `owners` 命令补登记，重启 Hermes 生效，不必重跑向导。其他人、机器人、认不出是谁的话不记也不查；这一版所有聊天平台的群聊都不记也不查，包括你本人在群里说的话。（**已知例外，待修：** 原委按 Hermes 报的聊天类型判断，下面这几种多人聊天里，原委对已登记的本人照常启用：Discord 服务器（Hermes 默认把在频道里 @ 机器人的每条消息挪进一个新帖子，所以服务器里的对话大多算在内；只有回复、关了自动开帖的频道仍不记）、Slack 多人私信、LINE 多人房间、被 Hermes 当成私聊的 Matrix 房间（比如没起名字、标成私聊、却有三个人以上的房间），以及你把自己登记成 `api_server` 本人时、别的机器上的 Hermes 通过 API 发给你机器人的群聊轮次（这样发来的每一轮都当成你的话，不管群里是谁说的）。你本人的话仍会被记下，助手在那里也能翻你的记忆，回的话那里的人都看得到。私事只在真正的一对一里聊。）Hermes 自己的配对、白名单只说「谁能用机器人」，不算「谁是你」。
4. **Hermes 自带的记忆照常开着。** Hermes 自己有一份小笔记，记你的偏好和要点（设置里是 `memory.memory_enabled`、`memory.user_profile_enabled`，默认都开）。原委不关它，只占「外接记忆插件」那一个位置（Hermes 同一时间只能接一个）；两者并存：它的笔记每轮都在，原委存全部原话、按需去查。
   要知道两点：① **「别用记忆」的开关只管原委自己**，Hermes 自带的笔记照样会放进上下文；② 想让原委单独负责记忆，可以自己在 Hermes 的设置里把那两个开关关掉（原委不替你改）。Hermes 的「技能」本身和原委互不相干，技能的包装文字不进记忆；0.1.0a10 起，在桌面版和聊天平台上你发 `/技能名 你打的话`，原委记你打的那几个字（光 `/技能名` 不带话不记，终端里不记；只在 Hermes v0.23.2 上核过，见下面「0.1.0a10」一节）。
5. **每个机器人一个库，新机器人要单独装一次；群聊和机器人之间互发的消息，这一版不记也不查（有几处已知例外，见第 3 件事）。**
   - Hermes 新建机器人时，会把主 Hermes 的设置整份复制过去，原委也在里面。原委认得出这种「复制来的设置」（装的时候在 `config.json` 里记了它属于哪个家目录，插件启动时核对）：**不启用**，不读、不写、不交工具，也不会碰主 Hermes 的库；`yuanwei status hermes` 和插件状态里写 `copied_from_other_profile`，并告诉你怎么办。
   - **老的设置（这一版之前装的、没有记家目录）而且库放在自定义位置的**：原委没法确认它属于哪个档案，所以先不启用（状态写 `ownership_unconfirmed`，不是「确定复制来的」），免得悄悄用到别的档案的库。对那个家目录重新跑一次向导确认：要继续用那个库就加 `--db <库文件>`，要用自己的新库就不加（旧库不动）；确认时会登记当前家目录，之后才启用。库在标准位置（`<家目录>/yuanwei/yuanwei.sqlite`）或这个家目录自己的目录里的老设置，照常用。
   - 要让某个机器人用原委：对它的目录跑一次向导，例如 `yuanwei setup --hermes-home ~/.hermes/profiles/<机器人名>`（不指定目录、又有机器人时，向导会先问你装给哪一个）。计划里会写「这是给机器人 <名字> 装，它会有自己单独的一个库」；它的库、设置、状态都放在它自己的目录下；复制来的旧 `config.json` 先备份。
   - 如果新建机器人时连库文件也一起复制过去了（Hermes 的 `--clone` 会整个复制 `yuanwei/` 目录），那份库里带着主 Hermes 的对话。**原委默认不沿用它**：计划里写明「这个机器人目录里有一份从别处复制来的记忆库，不沿用，挪到 <原名>.copied-from-<来源>-<时间>」；你确认计划以后，才把库文件和它的附属文件（`-wal`、`-shm`、`.d` 目录等）挪到同目录的那个备份名（不删、权限照旧），机器人从空库开始；不要那份备份的话你自己删。
   - 这一版只管**你和某一个机器人的一对一**。所有聊天平台的群聊、频道、论坛（宿主标记为 `group`、`channel`、`forum`），以及 Hermes 机器人群聊（平台 `bot_room`），都不记不查；你本人在群里说的也一样，配了 owners 不放行（原因 `group_room_not_supported`）。**已知例外，待修：** Discord 服务器里的帖子（宿主标 `thread`；Hermes 默认把频道里 @ 机器人的消息自动开成帖子，所以服务器里的对话大多是这种）、Slack 多人私信（宿主也标 `dm`）、LINE 多人房间（宿主标 `room`）、被 Hermes 当成私聊的 Matrix 房间（宿主标 `dm`），以及登记了 `api_server` 本人时别的机器上的 Hermes 群聊发来的轮次（宿主标 `api_server`、`dm`；每一轮都当成你的话）不在这几种里，原委照常启用，见上面第 3 件事。机器人之间互发的消息（带机器人作者标签）不记，也不让它查。想让它记住群里定的事，回到一对一里说一句（聊天平台上要用已登记的本人账号私聊）。

## 第一步：装（安装向导）

需要 Python 3.11 以上（装包用的 Python 和 Hermes 自己用的 Python 可以不是同一个，只要版本够，装的时候会记下包的位置给插件和后台进程用）。预览版发布到 PyPI 以后：

推荐先给原委单独建一个环境，放在 `~/.yuanwei/venv`（和自带向量引擎的 `~/.yuanwei/engine/` 放在一处，不打架），后面的命令都写完整路径：

```
python3 -m venv ~/.yuanwei/venv
~/.yuanwei/venv/bin/pip install yuanwei
```

不想建环境，就用 `python3 -m pip install yuanwei`（不要直接写 `pip`：有的电脑上只有 `pip3`）。

发布之前，也可以用本地的安装包装（不联网也能装，缺什么会直接报出来，不会自己去下载）：

```
python3 -m venv ~/.yuanwei/venv
~/.yuanwei/venv/bin/pip install --no-index --no-deps yuanwei-0.1.0a10-py3-none-any.whl
```

**重装／升级：** 升级只要一条命令：`~/.yuanwei/venv/bin/pip install --upgrade yuanwei`（没建环境的用 `python3 -m pip install --upgrade yuanwei`），然后重启 Hermes 网关（`hermes gateway restart`），用桌面版的把它退出再打开；记忆库和设置都保留。不重跑向导的话，Hermes 家目录里 `plugins/yuanwei/plugin.yaml` 的版本号会停在你上次跑向导时那一版，Hermes 的插件列表里也可能显示这个旧版本号；这不影响使用（原委不读这个版本号），实际在用的版本以 `~/.yuanwei/venv/bin/pip show yuanwei` 为准。只有某一版的发布说明写了「插件文件变了」时，才需要再跑一遍向导（0.1.0a8、0.1.0a9、0.1.0a10 不需要：只有 `plugin.yaml` 里的版本那一行变了。别只为了改这个版本号重跑：重跑时本人名单按这一次输入的重建，见下面「重跑 setup 时」）。再跑向导时，计划里会分「新放的文件」和「更新的文件」两类；已装的插件文件如果还是装的时候的样子（你没改过），就换成新的，换之前先各备份一份（`<原文件名>.yuanwei-backup-<时间>`，权限和原文件一样）；你改过的不覆盖，向导会拒绝并告诉你是哪个文件。设置文件 `config.json`、`yuanwei.toml` 同理。

然后在终端里跑向导，一路选下来：

```
~/.yuanwei/venv/bin/yuanwei setup
```

（`yuanwei` 不在系统路径里很正常，用完整路径就行；下面和装完的提示里的 `yuanwei …` 都是同一个意思，向导最后会把你这台电脑上的完整路径写出来。输入 `~/.yuanwei/venv/bin/yuanwei --help` 能看到给用户用的全部命令。）

向导会依次：检查环境（Python、Hermes、接口是否对得上）→ 选助手（现在只有 Hermes；Claude Code、Codex、Pi 是后续更新）→ **选预设** → 选整理用的供应商和模型（列表最后有一项「**不整理**」，选了就跳过供应商和密钥，不需要密钥、不花钱；推荐仍是整理）→ 设整理用的密钥 → 选要不要开本机向量 → 第 7 步选读取范围、按检测到的聊天平台逐个问本人账号 → **列出计划** → 你确认了才改东西。没检测到聊天平台就不多问账号；某个平台可直接回车跳过，多个本人编号用逗号分开。**确认之前什么都不改；任何一步输入 `q` 或按 Ctrl-C 都是取消，什么都不会改。**

**四个预设**（后面每一步按它给默认值，你也可以逐项改）：

| 预设 | 整理 | 检索 | 标签 |
|---|---|---|---|
| 推荐 | DeepSeek `deepseek-flash` | 关键词＋本机向量（要下载一个约 600 MB 的模型，计算都在你自己的电脑上） | 整理测过；向量：LM Studio 是测过的那一套，自带程序和它几乎一样、没过我们自己定的严格标准 |
| 轻量 | DeepSeek | 只用关键词，不下载任何东西（以后可以 `yuanwei vectors setup` 再开） | 整理测过；只用关键词的答题效果没测过 |
| 自选 | 自己选供应商和模型 | 自己选 | 没测过 |
| 全本机（实验） | 你电脑上的大模型 | 本机向量 | 实验：效果没测过，吃内存，对话不出电脑 |

**整理用的供应商：** DeepSeek（测过，默认）；OpenAI `gpt-6-luna`（试过：11-06 在旧故事上整理了两串，新故事没测；按美元记账）；月之暗面、阿里云百炼、智谱、硅基流动、OpenRouter 和「手填」是没测过的（整理的提示词只在 DeepSeek 上调过；地址未核，模型名要你自己填）。没有价格表的供应商，**原委的费用估算和每日预算上限对它不准、可能不起作用**，花了多少以对方平台上看到的为准。

**不整理（0.1.0a7 起）：** 整理是用一个大模型把对话归到各条主线上，要密钥、要花钱。也可以不整理：向导里选「不整理」，或不问话的写法加 `--no-organize`；装好以后随时 `yuanwei organize off --yes`（关）、`yuanwei organize on --yes`（开）、`yuanwei organize status`（看；不加 `--yes` 只列计划），改完重启 Hermes。关着时：原话照常存、照常查（关键词和向量都照常），封步也照常，只是不拉起整理、不发请求、不要密钥；查回来的原话不挂「未整理」；`yuanwei status hermes`、`status` 工具显示「整理：关」和「关着时封好的 N 步，打开后按封步顺序补」；`doctor`、`status hermes`、`key status` 不把「没有整理密钥」当成问题。再打开时，关着时封好的步按顺序补，结果和一直开着整理一样。没有主线，「主线往前排」「补同一回」就用不上，直接命中的原话照样一条不少。默认仍是整理开着；重装不带 `--no-organize` 时沿用已有的开关。

**整理用的密钥：** 向导只报「有没有、来自哪里」（不显示、不打印它的值）。**已经有的话会问你「用它吗？[Y/n]」**：回 n 就另输一把（输入时不显示，存进原委的**全局**密钥文件，读的时候排在环境变量和 Hermes 设置文件前面；这个机器人要是自己单独设过密钥，那份还排在最前面，向导会提醒）——比如已有的那把是要作废的。从外面运行 `yuanwei status hermes` 时，环境变量里没有，会再看 Hermes 的 `.env` 里有没有这个**名字**（只看名字，不读值），有就写 `hermes_env_file`（Hermes 运行时会自己读它）。没有的话你可以：① 在向导里输入（输入时不显示，存进全局的 `~/.yuanwei/keys/<变量名>`，权限只有你能读；几个机器人共用这一份）；② 自己写进 Hermes 的设置文件 `~/.hermes/.env`（`DEEPSEEK_API_KEY=…`），或在启动 Hermes 的终端里 export；③ 以后再说。也可以单独运行 `yuanwei key set`（交互式、不显示，存全局）、`yuanwei key status`（只报来源，不显示密钥的值：真正会用到的是哪一份、来自哪里，再分别说全局文件和这个机器人自己的文件在不在、类型和权限对不对——这几项不代表里面的值合格；也看 Hermes 的 `.env` 里有没有这个名字）、`yuanwei key test`（用真正会用到的那一份；先问，再发一个最小的请求，花不到一分钱，只报「能用／不能用／没验成」）、`yuanwei key delete --yes`（删全局）。

**密钥全局一份，几个机器人共用；某个机器人要用别的，可以单独给它设：** `yuanwei key set --this-bot-only --hermes-home <那个机器人的家目录>`（`key delete --this-bot-only` 删这一份）。存全局以后，命令会列出它找到的、有自己单独密钥文件的机器人（能用的话会先用它，不用全局这把；实际用哪把看 `yuanwei key status`，对别的机器人要加它的 `--hermes-home`），并告诉你怎样删掉那份、好让它改用全局的。这个列表只查了主家目录、它下面的 `profiles/*` 和你给的 `--hermes-home`，没有查全。读的先后：**这个机器人自己的密钥文件 → 全局密钥文件 → 环境变量**（`status hermes`、`key status` 里再多看一眼 Hermes 的 `.env`）。只有装的时候写进配置的（向导装的都有）才会去看这两个文件；配置里没有的只看环境变量。这个系统没法把文件权限设成只有你能读的（不是 Mac／Linux 这类），不存密钥文件，也只认环境变量。已经装好的不用动：升级以后自动往全局找。全局目录可以用环境变量 `YUANWEI_KEY_DIR` 改：**只认绝对路径**（可以用 `~` 开头；写成相对路径会报错、原委不用它）。这个目录会被设成只有你能读（0700），请用专门放密钥的目录，不要填共享目录或项目根目录；你自己的终端和 Hermes 服务要用同一个设置，不然两边看到的不是同一份。

`key status`／`key test` 查的是「整理实际用的那一份」：装好了就按配置里记的密钥文件路径查；还没装就按装好以后的标准位置预览（输出里会写明是预览）；用 `--api-key-env` 指定了和配置里不一样的变量，会写明查的是你指定的变量、不是当前整理配置。`--this-bot-only` 只管标准位置，配置里记的是别处的自定义文件时，它不会动那份文件（命令会说明）。输出只报来源，不显示密钥的值。

**本机向量：** 向导检测本机有没有 Ollama、LM Studio（命令在不在、本机服务有没有响应）。有就问你用哪个；**模型不在本机时，问过你、你同意了才让它下载**（这两种方式是由你电脑上的 Ollama／LM Studio 去它们的官方模型库下，原委自己不下载；选下面的「自带向量引擎」则是原委自己下载，下载前同样先问你）；原委**不替你安装、不替你启动** Ollama 或 LM Studio，只告诉你去哪里装：Ollama https://ollama.com/download ，LM Studio https://lmstudio.ai 。装好后会核验：算几句测试的话，核对维度、确定性，记下编码身份；核验不过就不写任何配置。LM Studio 的身份尽量取强：模型文件的 SHA-256（`lms ls --json` 给的是相对路径，拼到模型目录上——`~/.lmstudio/settings.json` 里的 `downloadsFolder` 只读这一个键，没有就 `~/.lmstudio/models`，再兼容旧位置 `~/.cache/lm-studio/models`）、运行包版本（`lms runtime ls` 里带 ✓ 的那一行）、加载时的上下文长度（`lms ps --json` 里已加载的实例；取不到才退回模型的上限，并标明是上限）。哪一项取不到，身份标「弱」，装完会写出是哪一项；**「测过」按身份比对，分三档**（测过的身份：LM Studio 本机兼容接口、模型 `text-embedding-qwen3-embedding-0.6b`、模型文件 SHA-256 `06507c7b…c3e439`、加载上下文 2048、无前缀无模板、L2 归一化、维度 1024、运行包 `llama.cpp-mac-arm64-apple-metal-advsimd@2.53.0`）：全都一样才写「测过（和测过的设置完全一样）」；只有运行包版本不同写「同一个模型文件和设置；LM Studio 的引擎版本不同（测过的是 2.53.0，你的是 X），算出的向量可能有极小差别，这个版本没核过」；模型文件对不上、取不到（身份弱）、上下文或维度不同，写「没测过」并列出哪几项不同。计划里（核验前的预判）、装完的那一行、`yuanwei status hermes` 的 `vectors.tested_comparison`（`level`、`differs`、`text`）都按这三档写。别的运行方式（Ollama、自带引擎、手填）没有测过的身份，一律「没测过」。NumPy 要装在 **Hermes 实际导入包的那个 Python 环境**里（不是启动脚本里的 `#!/bin/sh`，也不是更新前留下的旧环境）：原委先问 Hermes 自己（`hermes --print-runtime-command`，读它真实的 `sys.path`），找到的环境还要核过——真的是 Python、版本 3.11 以上、和 Hermes 实际用的是同一套；找不到就直说，向量退回只用关键词，你可以用 `--hermes-python` 指一个。没有 NumPy 的话先把**完整的安装命令**列在计划里（那个环境没有 pip 时用 Hermes 自带的 uv：`<uv> pip install --python <环境>/bin/python 'numpy>=1.26'`），问你能不能装，不同意向量就关掉。**原委已经正式告诉 Hermes 它需要 NumPy**：插件文件 `plugin.yaml` 里声明了 `numpy>=1.26`（一律声明，不管开不开向量，只用关键词的人也会多装约 5 MB）。Hermes 重建自己的包环境时会按声明自动带上（按 Hermes 源码：下次启动或更新时发现环境和声明对不上就会重建；在 Hermes v0.22.0（+10397，2026.9.24）上已经在真机上确认过，重建两次，NumPy 都自己装上了；其他发行方式没验证）；上面那条命令是现在就装进当前环境。万一还是丢了（比如 Hermes 重建了环境、而声明还没生效），向量自动退回只用关键词（不会出错），再运行同一条命令就能装回；`yuanwei status hermes` 的 `numpy_in_hermes` 会告诉你现在有没有、插件里有没有声明、没有的话补装的命令是什么，并说明可能是 Hermes 重建了环境。以前装过的，重新运行一次向导，`plugin.yaml` 会列在「更新的文件」里（先备份），声明就进去了。向量服务默认只许本机地址；要用别处的服务必须加 `--allow-remote-embedding`，那样你的原话（切成句子）和每次查询都会发给它。

**自带向量引擎（推荐，现在只支持 Mac 的 M 系列）：** 原委替你准备 llama.cpp 官方发布的服务程序和 Qwen3-Embedding-0.6B 的 Q8 模型文件，放在 `~/.yuanwei/engine/`。**下载之前先问你、说清每样多大，你同意了才下**；下载来的文件先核对原委这一版钉住的校验码（SHA-256），对不上就删掉、不会运行；整个运行包的每个文件每次启动前都核一遍。你电脑上如果已经有同一个模型文件（比如 LM Studio 里下过的），只读地直接用它，不再下载，也不动它。向量程序只监听本机（127.0.0.1），用本次启动专用的随机凭据，不走代理、不跟跳转；它的原始输出一律丢弃、不落盘。它在用到的时候由后台小进程拉起，闲着 15 分钟自己退出；隔了很久再回来的第一次提问可能赶上它还没起来，这一次只用关键词（状态里写 `engine_starting`）。卸载原委时会问要不要一起删它（默认不删）；`yuanwei vectors remove-engine --yes` 也能删。**这一版钉住的是 llama.cpp 的 `b11701`（ggml-org 官方发布，2026-10-16；Mac M 系列的 tar.gz，程序约 12 MB，解开约 32 MB）和通义千问官方的 Qwen3-Embedding-0.6B Q8_0（约 610 MB，Hugging Face 或魔搭下载；官方文件和测过的是同一个文件，SHA-256 相同）。** 压缩包和运行包里的每个文件的大小、SHA-256、可不可执行、包内链接的目标，都在 2026-11-11 真机上核过并钉死在表里。**一致性（2026-11-11 真机核过）：测过的只有 LM Studio。** 自带程序用的是同一个模型文件，向量和 LM Studio 算的几乎一样（全量 11,588 句里 8 句略低于我们定的线，最低 0.9977，没有低于 0.995 的），但正式抽样（1,000 句）里有 2 句低于 0.999，没过我们自己定的严格标准，所以向导的计划、核验后的那一行、`yuanwei status hermes` 的 `vectors.tested_comparison`、`yuanwei vectors status` 的 `engine.installed.model_label` 都写「同一个模型文件；向量和 LM Studio 算的几乎一样（…），没过我们自己定的严格标准，所以不能当成和 LM Studio 那套完全一样」，不写「测过」、不写「一致」。这条结果只属于这一版引擎（b11701）、这个运行包和这套启动配方：换了任何一样，就回到「一致性还没在真机上核」。向导第 6 步仍然推荐自带（不用装别的软件，最方便）；想用测过的那一套就选 2) LM Studio。系统如果拦住这个程序，原委只告诉你情况和 Apple 自己的办法，不会去改系统的安全设置。

**向量是后台慢慢补算的：** 库里已有的原话要一条条算，算好之前「找」只用关键词，`yuanwei vectors status` 会写还差多少、最近一次失败的原因。向量服务没开、连不上时这一次只用关键词（状态里标出来），后台暂停并退避，恢复后自己接着补。编码身份（模型、量化、运行方式）变了，旧向量不再用，全部重算；服务自己变了（比如升级了 Ollama）会暂停并提示你 `yuanwei vectors setup --reverify`，不会悄悄全部重算。旧身份留下的向量用 `yuanwei vectors prune --yes` 清。

### 聊天平台：登记、查看、删除本人账号

在你与 Hermes 的**私聊**里发 `/whoami`，核对它显示的平台名和本人用户编号；微信的平台名是 `weixin`，安装微信时显示的 User ID 也可用来核对。编号不是显示名，也不是机器人的 `WEIXIN_ACCOUNT_ID`；也别把共用、自动的发送者编号（比如 API 的 `api`、webhook 的路由）登记成你。白名单、配对只能帮你核对，原委不会自动把名单里的人当成你。

下面的 `<家目录>` 和 `<本人编号>` 要换成你自己的值；给哪个机器人登记，就用哪个机器人的家目录。不写 `--hermes-home` 时使用默认 Hermes 家目录。

```sh
# 只查看；不写平台名就列全部平台
yuanwei owners list --hermes-home '<家目录>'
yuanwei owners list weixin --hermes-home '<家目录>'

# 先看计划；加 --yes 才改
yuanwei owners set weixin --id '<本人编号>' --hermes-home '<家目录>'
yuanwei owners set weixin --id '<本人编号>' --hermes-home '<家目录>' --yes

# 删除一个编号；不写 --id 就删除该平台的全部登记
yuanwei owners delete weixin --id '<本人编号>' --hermes-home '<家目录>' --yes
yuanwei owners delete weixin --hermes-home '<家目录>' --yes
```

**`set` 是替换该平台的整份名单，不是往旧名单里加一个。** 有多个本人账号就重复 `--id`，把要保留的都列上；其他平台的登记不变。`delete` 不加 `--yes` 也只列计划。`owners` 的查看、计划和结果会显示相应的账号名单；`status/doctor` 只报登记数量，不显示编号。删除登记只影响重启后的接收和读取资格，不会删除之前的记忆。

这些小命令只改原委自己的 `config.json` 和安装记录里的对应指纹，修改前会备份；不改 Hermes 的 `config.yaml`、网关白名单或密钥。**修改后要你自己重启对应的 Hermes**（结果会提示 `restart_hermes`），运行中的插件不会自动重读名单。

平台检测只看目标家目录的设置，以及已知启用项有没有配置，不连接平台，不能证明已登录或在线。复杂 YAML 或没覆盖到的动态配置可能检测不全，输出会提示已发现的问题；知道平台名和本人编号时仍可用 `--owner` 或 `owners set` 明确登记，不能把「没检测到」当成「没有平台」。

### 全参数写法（不问话，给脚本和助手用）

给了助手名就不问话；不加 `--yes` 只列计划（什么都不改）：

```
yuanwei setup --host hermes --preset light                            # 只列计划
yuanwei setup --host hermes --preset light --yes                      # 真的装
yuanwei setup --host hermes --preset recommended --vectors ollama --download-model --yes
yuanwei setup --host hermes --preset custom --provider openai-luna --api-key-env OPENAI_API_KEY --yes
yuanwei setup --host hermes --preset local --vectors none --provider-model <本机模型名> --yes
yuanwei setup --host hermes --preset light --owner 'weixin:<本人编号>' --skip-owner telegram --hermes-home '<家目录>' --yes
```

| 参数 | 含义 |
|---|---|
| `--host hermes` | 助手；只有 hermes |
| `--preset recommended｜light｜custom｜local` | 预设；不给＝light（推荐、全本机要同时给 `--vectors`） |
| `--provider`、`--provider-url`、`--provider-model`、`--provider-param 键=值` | 整理用的供应商；只发列出来的参数；非本机地址只许 https |
| `--api-key-env 变量名` | 密钥从哪个环境变量读。**参数写法里不收密钥本身**（参数会留在 shell 历史和进程列表里）；要存密钥请在你自己的终端里运行 `yuanwei key set` |
| `--vectors none｜llamacpp｜auto｜ollama｜lmstudio｜custom`、`--embedding-model`、`--embedding-url` | 向量。`llamacpp`＝自带引擎（现在只支持 Mac 的 M 系列；别的系统显示「暂不支持」，可以用 LM Studio 或 Ollama）；`auto`＝支持就自带、不支持就报错，不悄悄换别的 |
| `--download-model` | 同意下载计划里列出的全部东西（自带引擎：程序和模型；Ollama／LM Studio：向量模型）（**`--yes` 不等于同意下载**） |
| `--engine-dir`、`--engine-url`、`--model-url`、`--model-file` | 自带引擎放哪里（默认 `~/.yuanwei/engine`）；换程序／模型的下载位置（只许 https，校验码仍然是原委钉住的那一个）；用你自己的一个模型文件（SHA-256 对不上就拒绝） |
| `--install-numpy`、`--hermes-python` | 同意往 Hermes 实际用的 Python 环境里装 NumPy（装的命令计划里会写全）／指明装包环境的 Python（要和 Hermes 实际导入包的是同一套，对不上会拒绝） |
| `--allow-remote-embedding` | 允许向量服务在本机以外 |
| `--ignore-probe-failure` | 本机大模型的长输入探针没通过也照装（自己承担） |
| `--owner 平台:本人编号` | 登记本人；可重复，同平台的多个编号组成名单。不从白名单自动填 |
| `--skip-owner 平台` | 跳过该平台登记；可重复，与同平台的 `--owner` 不能同时给。未登记的平台不记也不查；跳过不等于保留旧登记 |
| `--read-scope`、`--mode`、`--db`、`--config`、`--spawn`、`--replace-provider`、`--hermes-home`、`--hermes-cmd`、`--config-method` | 沿用原来的写法 |

现有的 `yuanwei setup hermes …`（不带供应商和向量参数）仍只装插件，不碰供应商和向量；同样接受 `--owner` 和 `--skip-owner`。**已经用向导装过的，别用这个简写重跑**：它按这一次的参数重写 `config.json`（旧的先备份），不再指向向导写的 `yuanwei.toml`（那个文件还在，但插件改按默认设置跑，向导选的整理、向量设置不再生效），读取范围、本人名单也按这一次的参数重建。非交互安装不会逐个平台追问，没给本人编号的平台会在计划里提醒、不阻止安装；安装后仍不会记这些平台的话。

**重跑 setup 时，本人名单按这次输入重建，不自动合并旧名单。** 需要保留的所有平台和本人编号都要重新列齐；跳过、或没给 `--owner` 的旧登记，确认安装后不会留在新配置里。只补或改账号请用 `owners set/list/delete`，不必重装。

**全本机预设的长输入探针：** 本机大模型服务的默认上下文常常只有几千个词元，会在你不知情时把整理要读的很长的输入截掉。装之前会发一段很长的输入（暗号放在最前面），核它能不能原样复述；复述不出来就不装。

### 让助手来装

把 `让助手来装.md` 交给 Hermes，说「照这个装原委」。助手只能用上面「全参数写法」里的命令，先把计划原样给你看，你同意了才加 `--yes`；**密钥由你自己在终端里设，不要贴给助手**；助手不替你装 Ollama／LM Studio，不自己重启 Hermes。

### 单独装、改本机向量

```
yuanwei vectors setup [--vectors ollama|lmstudio|custom] [--yes]    # 以后再开向量／换模型
yuanwei vectors setup --reverify --yes                                # 服务变了以后重新核验、记新的编码身份
yuanwei vectors status [--check]                                      # 只读；--check 会去探一次本机服务
yuanwei vectors prune --yes                                           # 清旧编码身份留下的向量
```

如果 `memory.provider` 原来是别家（比如 honcho），它会拒绝并告诉你原值；确认要换，加 `--replace-provider`（原来的值会记下，卸载时还原）。

**它会改什么：**

- 在你的 Hermes 家目录（默认 `~/.hermes`，也可以用 `--hermes-home` 指）里放这些文件：`plugins/yuanwei/__init__.py`、`plugins/yuanwei/plugin.yaml`、`yuanwei/config.json`（你的读取范围、主人名单、记忆库位置），向导装的还有 `yuanwei/yuanwei.toml`（整理供应商、检索方式、本机向量；**里面没有密钥**，只有变量名和密钥文件的路径），再加一份安装记录 `yuanwei/install.json`。
- 改 `config.yaml` 里 **`memory.provider` 这一行**，改成 `yuanwei`。能用 Hermes 自己的命令（`hermes config set`）就用它改，没有才直接改这一行；**改之前先备份** `config.yaml`（备份文件叫 `config.yaml.yuanwei-backup-时间`）。
- 记忆库默认放在 `<hermes 家目录>/yuanwei/yuanwei.sqlite`（`--db` 可以改地方）。后台子进程的输出写在 `<库>.spawn.log`，`yuanwei status hermes` 里能看到最近几行（过了密钥过滤）。
- 选了「自带」向量引擎并同意以后，会在 `~/.yuanwei/engine/` 下放程序和模型（可用 `yuanwei vectors remove-engine` 删）。
- **不会**改 `CLAUDE.md`、`AGENTS.md`、`SOUL.md` 这类说明文件；**不会偷偷联网**（下载只在你同意之后：用 Ollama／LM Studio 时，是它们去下向量模型，原委自己不下；用自带向量引擎时，原委自己下载程序和模型；你同意往 Hermes 的 Python 里装 NumPy 时，会由 pip 或 uv 去下载；每一种都会先问你。你选了向量，原话才会发给你配置的向量服务；整理用的模型当然要联网，除非你选了全本机）。

**装好以后要重启 Hermes**，新的记忆提供者才会加载。装好以后看状态：`yuanwei status hermes`（里面有「整理」「整理供应商」「向量」「内部错误」几项），或 `yuanwei vectors status`。

**怎么撤回：** 见第四步；或者手动把备份的 `config.yaml` 放回去。卸载**不删**你的记忆库和密钥文件（要删全局密钥文件用 `yuanwei key delete --yes`，这个机器人自己单独的那份加 `--this-bot-only`）。

## 第二步：用

装好重启以后，平时就正常聊天，不用做别的：

- 每一轮**完成**的对话（你说的和助手最终回的；助手在几次工具调用之间说的话不存，只存最终回复），本人身份通过核对的才会被记进当前所在的工作区；聊天平台还必须是一对一。群聊（包括你本人在群里说的话；几处已知例外见开头第 3 件事）、你按了「停止」（`/stop`）的轮次、机器人、定时任务、子代理的话不记。助手没答完时你又发一句（Hermes 的改口、插话）不算按停止，0.1.0a9 起一般照存，例外见下面「助手没答完时你又发的话」。
- 默认**只给工具、不主动塞材料**：助手需要翻历史时自己调 `recall`（查记忆）、`get_messages`（按编号取原话）、`attachments`（看一条消息挂到哪里）、`status`。（这些工具能不能出现在助手的工具列表里，还取决于你 Hermes 的工具集设置：默认设置下，作者自己日用的 Hermes v0.23.2 上助手会自己调 `recall`；改过工具集设置的没核过。）
- **先交名次靠前的，再在页内按时间排。** `recall` 的第一页先装检索名次靠前的命中组；一条命中及它带出的邻近句、同回材料放在同一页，每页仍有会话和日期。多个工作区一起读时，先轮流取各区的第 1 组，再第 2 组，依次分页。单组超过页上限或宿主硬上限时会明确说装不下，需缩小查询或按消息编号读取。升级前的 recall 游标会提示「请重新查」；同一新游标重复取页内容相同。
- **每次查询交多少。** 助手调 `recall` 不带额度时，一次总共选约 8,000 估算词元（按同一把尺子量，中英文一样）；助手主动要更大的 `budget`，上限 24,000。一页最多 14,000 估算词元。默认额度装不下单条很长的消息时，这一次自动放宽到 24,000 再试；还装不下就报「找到了相关内容，但这条消息太长放不进额度」，不会回「没有找到相关记录」。便条（每轮自动给的那份）另有 4,200 词元的上限；在 Hermes 里，自动预取的字数上限照 Hermes 自己的设置（默认 100,000 字符，开了预取溢出则是它的 max_chars，读不到时按 10,000 保守处理）。设置文件里自己写了 `first_budget` 或 `total_budget` 的照旧生效。
- **查不到时不硬塞材料（相关度下限）。** 助手调 `recall` 时，一条原话要进候选，得满足二者之一：有关键词命中；或者向量模型已标定、这条的向量余弦分数不低于为这个模型量出来的下限。没有任何一条够格，`recall` 返回「没有找到相关记录」，不附材料，也不给续读提示（多个工作区一起读时，没命中的工作区不出空段落；有的工作区有命中时，开头「读取范围」一行仍列出读过的全部工作区；全都没命中就只回这一句）。有候选时，每条原话的标头写明怎么找到的：`关键词命中`、`仅意思相近｜余弦 0.xxxx`，或 `附带邻近材料／附带同回材料（关联 编号）`；附带材料是随命中的原话一起带出的前后句和同一回，不是它自己过了下限。原话本身不改写。
  - **这不是「无答案检测」。** 下限只决定哪些原话够格当候选；它判断不了你的记忆里有没有答案，也不保证不相关的问题一定空手而归：我们自己的小规模构造测试里，留出的 24 条不相关问法有 6 条仍放进了至少一条原话（见产品规则表末尾）。
  - **没标定的向量模型只用关键词。** 下限是按「模型文件＋输入处理方式」登记的。现在登记过的只有 Qwen3-Embedding-0.6B-Q8_0 这一个文件（LM Studio 下实测过；同一个模型文件不管用哪个运行程序，包括自带向量程序，都沿用同一个门槛，运行程序不在实测名单上的，状态里注明「当前运行程序未实测」，**自带程序这条路没有在真机上测过**）。别的模型文件、量化、输入处理没登记，读取就只用关键词命中，不去算查询向量；这时换了说法的内容可能找不到。`status hermes` 的 `relevance`（以及 `yuanwei vectors status`）会写明「语义阈值未标定」和原因，并提示换回已标定的推荐向量模型；缺少或无效的编码身份是另一回事，写「混合检索不能运行」，不假称已降级。
  - **升级前建立的旧检索游标会失效**，提示重新调用 `recall`；按编号读原话（`get_messages`）的旧游标照常能续。
- **记忆读取的开关是按「对话窗口」管的**（11-10 起）。一个窗口就是你和助手的这一段对话；压缩、重启不换窗口；`/new` 是新窗口；`/undo` 不改开关。`/branch` 分出来的是新窗口，之后各管各的；Hermes v0.23.2 不会把 `/branch`、`/resume` 通知原委，所以 0.1.0a10 起的做法是：原委没见过的对话，如果 Hermes 说它一开始就带着以前的内容（来自恢复、分支或轮外压缩），而你的原委库里此刻有任何一个对话关着记忆，这个新对话就先关着，并告诉你一句；要用，在消息第一行写 `#yuanwei-mem`。没有任何对话关着时，分出来的对话是开的。子代理、定时任务不能读，也不能开。
  - **关：** 说「别用记忆」这类话、在消息第一行写 `#yuanwei-nomem`、或者助手调关闭工具，**任何一样都关**。关了以后，这个窗口**每一轮**都不翻记忆（包括「便条」「目录」），直到你重新打开；助手每轮会收到一条回执，说明读取是关着的、怎么打开。
    **能保证的只有口令**（和设置里的开关）；大白话的「别用」靠助手听懂、再加上程序里的规则认出，**可靠度没量过**，认不出的会漏。这一版还补了几种说法（「不要和记忆核对」「我不希望你再用记忆」「不想让你看以前的对话」「现在不要查」「先不开」等），宁可多拒、不可漏拒，所以偶尔会多关（比如「用不用记忆都行」也会关）。
  - **开：只有两种办法。** ① 在消息第一行写 `#yuanwei-mem`；② 你要助手用记忆时，助手调开启工具申请，程序登记一条「待确认」，助手把一句固定的话转告你：「要在这个窗口重新使用长期记忆吗？回复「确认开启」即可。」你的**下一条消息**第一行正好是「确认开启」（前后空白和末尾的句号、感叹号可以有）才打开；下一条是别的话，待确认就作废，窗口仍然关着，要重新申请。助手不能替你确认。
  - **设置优先：** 如果你在设置里把这个会话或工作区的读取关了，说什么都打不开，也不会改你的设置。
  - 这一版只管「本插件之后的新读取」：已经交给模型的材料、Hermes 自己的上下文，开关抹不掉，回执也不会说「已撤回」。**Hermes 自带的那份笔记也不归这个开关管**（见开头第 4 件事）。
  - 关闭要写进窗口状态才算数。写失败时，回执会说「没能确认已关闭」，并且这个窗口先不读；不会报成「已关」。
  - 关着的窗口，在你关上、打开、恢复一个关着的窗口时，各提示一句（提示在回执或状态里给；Hermes 上能不能直接显示给你，**真机上没核过**）。
- 想换成「回答前先查一张便条」或「只在开头给一份主线目录」：装的时候加 `--mode note` 或 `--mode directory`（默认是 `tools_only`）。这两种也照上面的读取范围读，读多个工作区时一样逐段标明出处。

已入库的新话不用等整理就能按关键词查到；安装采用的 `partial` 模式下，向量未算好或服务断开仍走关键词。`recall` 和便条只排当前这一轮；同一会话里更早的话（整理过的、没整理的）都能查到，向量算好后也按向量。工具页尾和便条说明列出未整理编号，原话正文不变。

带图的一轮保存原文字、图片张数和助手回答；只有图的一轮也保存张数和回答。图片及其临时本机路径不保存。若两次交接对不上，这一轮不存，原因和次数留在 `yuanwei status hermes` 的 `skip_reasons`（按库累计，原委实例换了（Hermes 重启、闲置久了、重新生成／撤回、`/retry`、换模型或改配置）也不会丢，只记原因和时间、不记原话；`skipped` 只是当前这个实例的数）。`doctor hermes` 核开始与同步两处文字拍平函数、图片提示和默认问句的构造、以及宿主交给记忆的那句话怎么取；缺失的检查写「没核」，变了写「变了」。已漏掉的旧图片轮次不会自动补回。

0.1.0a6 补：桌面版（和微信等走附件的平台）带图的消息在 0.1.0a5 上整轮没存（按 Hermes 真函数复现：宿主交给记忆的是用户打的字，`messages` 里那一行却带着图片路径提示，对不上；真机那一轮的原始形状没读过）。现在认这种形状，用户打的字原样存。宿主还可能在带图那一行后面追加召回内容或便条文字块，这种认不出，这一轮不存、记 `current_user_row_not_found`。

Hermes 可能给纯图自动补一句 `What do you see in this image?`；接口无法把它与用户真的输入同一句区别开，本版保留这句。宿主图片路径尾注按精确结构移除，用户较早写的同名字面提示仍保留；手工构造完全相同的消息结构无法证明尾注来源。

### 助手提问卡里的回答（0.1.0a8 起）

助手有时会用提问卡（Hermes 的 `clarify` 工具）一次问你几道题，你逐题点选或自己打字。这些回答在 Hermes 里是工具结果，不是你的消息，0.1.0a7 及以前都没存。现在会存：接在你这一轮那句话后面，每行带标签——`（助手问）`题目、`（助手给的选项）1）…／2）…`（助手给了选项就写）、`（用户选）`你点的那个、`（用户答）`你自己打的字。

- **只在一对一里存：** 本机（终端、桌面版），和原委核过的这几种私聊：微信、Telegram、Discord 的私聊，Hermes 在会话授权下的 API 会话，Slack 的一对一私信（编号以 `D` 开头的那种）。两种情况不存，这一轮照 0.1.0a7 存，计数里记 `clarify_dropped:shared_chat`：**共用的会话**（Discord 服务器里的帖子、Slack 多人私信），谁都可能答了你的卡，Hermes 的结果里又没有答题人；**原委还没核过的聊天软件**（WhatsApp、Signal、Matrix、飞书、邮件等，以及认不出的），哪怕是一对一，现在也还不存。
- **不存的：** 没答的、跳过的题；卡片的结束状态和提示文字；别的工具的输出。
- **和你直接发的话一样：** 提问卡里的回答（打的、点的）和你直接发的消息走同一套规矩：原样存，只有写成认得出的样子的密钥和密码（`sk-…`、`XXX_KEY=…`、「密码是 …」、`password=…`）会被挡掉；在提问卡里只打一个密码，前后什么都没有，会照打的存。
- **一轮太长：** 你那句话加上回答超过 1,500 字（整理的长消息线）时，先去掉「助手给的选项」那几行；去掉以后还超，就存去掉了选项的那份（回答一个字不少，这一条不送去整理，但照样能按关键词、向量查到）。长度按挡掉密钥之前的字数量；库里判长短按挡掉之后的，极少数卡在线上的会差几个字。
- **各平台不一样：**
  - 微信这类没有原生卡片的平台：卡片等回答时你打的字就是回答，原委照存。例外：打 `skip`（大小写都行）是跳过这道题，不存；以「/」开头的是命令，不是回答；打选项的编号（比如「2」）算点了那个选项，存成 `（用户选）`。
  - Telegram 这类有原生卡片的平台：一道**带选项**的题，你**没先点「✏️ 其他（输入回答）」**就直接打字，卡片会取消，Hermes 把打的字当成中途的话：0.1.0a9 起原委把那句字按中途的话存（见下面「助手没答完时你又发的话」，不算卡片的回答），已点好的回答也存（**只在假宿主上测过，没在真的 Telegram 上试过**；0.1.0a8 时这一整轮都不存）。打选项的编号或选项原文算点选；没有选项的题直接打字就是回答。想自己写，先点「其他」。
  - 你用 `/stop` 打断的那一轮，回答也不存（Hermes 不同步被打断的轮次）；只是又发了一句（没按停止）的那一轮，0.1.0a9 起照存，见下面「助手没答完时你又发的话」。
- **控制口令：** 在你自己的电脑上和上面列的一对一私聊里，你在提问卡里**打的**字和直接发的话一样算：口令和大白话的「关」都算，这一轮记下以后关上这个窗口的记忆读取，**从下一轮起生效**（同一轮里卡片之后助手已经查过的收不回来）。在 Telegram、Discord、Slack 上，要先点「其他」再打字、或者这道题没有选项，打的字才是回答、才这样算。点选的选项不算，那是助手写的字。**别的会话里在提问卡里打口令不起作用**，等卡片结束后直接发一条 `#yuanwei-nomem`。在微信上卡片等回答时，你发 `#yuanwei-nomem`、「别用记忆」都会变成卡片的回答（照上面算）。**回答里的 `#yuanwei-mem`、「确认开启」、「确认删除」一律不生效**，照常当回答存下；有待确认的开启或删除时，原委什么都不改，通常会在下一轮提示一句「上一轮在提问卡里的「确认删除」不算数，那次没有删；要删请重新提出删除。」（开启也一样；你下一条要是直接确认了、或窗口已经开着，就不提示）。打的「关」没写成的，也会在下一轮提示你再说一次。这些提示只在 Hermes 还是同一个助手时才有：Hermes 重启过、或对话闲置超过约一小时的，提示可能没有——删除、开启照旧不会发生，只是少了这句说明。要打开或确认删除，请等卡片结束后直接发一条消息。助手也被告知：确认开启、确认删除不要用提问卡问。
- **看计数：** `yuanwei status hermes` 的 `clarify` 一项按库累计：`answers_kept`（存下几条回答）、`turns_with_answers`（几轮里有回答存下），和下面这些备注各几次。**`clarify_*` 不是「这一轮没记」**：这一轮照常记了，备注说的是提问卡那一部分怎么了。没记的轮次看 `skip_reasons`。只有计数和时间，没有原话。
  - `clarify_dropped:shared_chat`：共用的会话，或原委还没核过的聊天软件，回答没收；
  - `clarify_dropped:unknown_shape`：结果的格式认不出（Hermes 可能改了格式，要核）；
  - `clarify_dropped:bad_json`：结果解不开，已知的原因是 Hermes 外发前的密钥清洗：卡上任何一处（题目、选项或你的回答）以 `OPENAI_API_KEY=…` 这类写法结尾，整张卡就被弄坏了，这张卡的回答都收不到；
  - `clarify_dropped:host_rewritten`：Hermes 自己把结果换成了固定的占位（压缩后的摘要、去重、溢出到文件、同一轮里一字不差的重复结果），回答收不到；
  - `clarify_dropped:unpaired`：结果和助手的调用配不上；
  - `clarify_dropped:turn_unclear`：认不清这些结果属于哪一轮（比如技能轮、两轮打了同样的字），回答没收；
  - `clarify_dropped:bad_text`：那道题里有坏字符，那道题没收；
  - `clarify_dropped:tag_in_text`：助手的题目或选项里有原委的标签字样，那道题没收；
  - `clarify_dropped:internal_error`：原委自己出了错，回答没收（错误另记在 `internal_errors`）；
  - `clarify_options_trimmed`：太长，去掉了选项行；
  - `clarify_long`：去掉选项以后还是超过 1,500 字，这一条不送去整理；
  - `clarify_control:closed`：你打的回答里认出「关」，关上了窗口；`clarify_control:close_failed`：没关成：本进程里先暂停读取，并（通常在下一轮）提示你再说一次；
  - `clarify_control:confirm_not_counted`：回答里有「确认开启」或「确认删除」，没生效，通常在下一轮提示你（Hermes 重启过或闲置超过约一小时的可能没有提示）。
- **删除列表：** `yuanwei conversations list` 每段对话的开头预览只取你自己打的那段，不带提问卡的标签。
- **体检：** `yuanwei doctor hermes` 新核两项。`clarify_result`：Hermes 构造提问卡结果的那几个函数，和核过的版本一样不一样（v0.21.6 到 v0.22.5 格式相同，报「对」，说明里写这几版点选的展示文字可能记成「用户答」）。`clarify_turn_markers`：认「这一轮从哪开始」用的技能脚手架开头和固定催促行的文字有没有变。变了就报「变了」；这时原委仍按严格格式解析，认不出的整条不收，这一轮其余照常记。
- **以前漏掉的回答**这一版不自动补回。

### 助手没答完时你又发的话（0.1.0a9 起）

助手还在答的时候你又发一句，Hermes 有两种处理：改口（Hermes 停下正在写的回答，把你的话当成更正，接着往下答；一般是它正在想、正在出字时你发的）和插话（Hermes 把你的话插在最近一次工具结果后面；一般是它正在跑工具时你发的）。0.1.0a8 及以前，这两种都让整轮不存（用户那句、助手回复都丢）；现在照存，你又发的话接在这一轮开头那句后面，一行一条、按发生的先后、带标签，和提问卡的回答排在同一串里：

- `（用户中途又说）`：改口，以及聊天平台上原委认得出 Hermes 加的来源说明的插话；
- `（中途插入·来源未核实）`：来源没法核实的插话。桌面版里嵌的预览页，脚本不用你点也能在助手忙时发一句，原委分不出这和你自己打的有什么不同，所以你自己电脑上的插话一律标这个；可见按钮和插件替你发的，和你打的一样存。
- **聊天平台（微信等）：** Hermes 会在你发的每一段字前面加三行来源说明（含账号编号），原委逐段去掉再存，一个字都不带进库；机器人发的段不存；JSON 解不开或去不干净的段不存。本机（桌面、终端）一个字不动。
- **只在一对一里收，**规矩和提问卡一样：共用的会话，和原委还没核过的聊天软件（WhatsApp、Signal、Matrix、飞书、邮件等，哪怕是一对一），这样的轮次整轮不存，计数记 `midturn_shared_chat`（带图、又只有改口的那一轮例外：存开头那句和回复，改口的字不收）；原委认不清这句话属于哪一轮时，只存开头那句和回复，中途的话一条不收。
- **口令：** 这样发的「别用记忆」会关上窗口（来源未核实的也算），每一段分别认；「确认删除」「确认开启」和 `#yuanwei-mem` 不算数，下一轮会说一声。
- **收不到的：** 你按了「停止」的轮次（Hermes 不交）；这一轮还没有工具结果时的插话（Hermes 把它插到这一轮开头那句的前面）；没赶上这一轮的插话（变成下一轮的开头，聊天平台上连来源说明一起，这是已有的问题）；Codex app-server 运行时的改口。
- **已知限制：**
  - 同一批里行序和说话先后可能反（同一次迭代里两条插话，宿主放进去的顺序和你说的顺序可能相反）。
  - 微信里带来源说明的一段和桌面塞的一段连成一行时分不开（后一段会跟着标成核实过的）。
  - 被丢掉的那几种段（来源说明认不得、机器人发的、外壳对不上）里的「关」可能没有任何提示。
  - 开头行被宿主并过、恰好又有同字的旧改口行时，一个普通轮可能不记（0.1.0a8 记得下）。
  - 首次压缩留下的头 3 行里是旧提问卡时，旧回答可能被重存一次。
  - 旧轮里只有插话、没有改口的这种情形认不出。
  - `get_messages` 翻页切在中途那一行中间时，下一页那一段没有标签。
  - 开头那句贴了没有结尾的私钥时，后面的中途行会被密钥过滤一起挡掉。
  - 服务端忙、客户端以为空闲时，桌面小部件的隐藏提示极少数会走改口，存成带「核实」标签的话。
  - 宿主自己开的轮（后台完成唤醒等）里你说的话不记，对账里算「没记」。
  - 同文的旧登记还留着时，可能把这一轮挂到别的轮次（少见）。
  - 中途的话写的时候只在假宿主上测过；2026-11-25 在隔离的真 Hermes v0.23.2 上跑过一次清点（见「0.1.0a10」一节），0.1.0a10 又在同一套上回归过、没有退步，但不是每种情形都逐项重试过；微信上的中途插话没在真的微信 App 上走过，Telegram 等别的聊天平台没在真机上试过。
- **看计数：** `yuanwei status hermes` 的 `clarify` 里多了 `midturn_kept`（存下几条）、`midturn_dropped:*`、`steer_dropped:*`、`midturn_control:*`；`skip_reasons` 里多了整轮没记的 `midturn_ambiguous`、`midturn_unmatched`、`midturn_shared_chat`。助手的 `status` 工具和 `yuanwei status hermes` 现在还给「开始几轮、记下几轮、没记几轮、宿主自己开的几轮」：没记＝开始了、库里没有它的话，也不是你要求删掉的、不是宿主自己开的；按了停止、没答完、上一轮还在存、库忙排队待补的也算在没记里；这些数也算升级以前的轮，以前版本丢的轮会算在「没记」里，0.1.0a9 以前 Hermes 自己开的轮分不出来，也算在「没记」里。
- **体检：** `yuanwei doctor hermes` 新核三项：`midturn_redirect`、`midturn_steer`、`midturn_envelope`（Hermes 里改口、插话、来源说明的写法，只读源码）。

### 0.1.0a10

2026-11-25 在隔离的真 Hermes v0.23.2 上（假模型、断网）逐功能清点过一遍「哪些轮会丢、会记错」，这一版修了其中一批；每条的规则在 `docs/产品规则表.md` 第 23 节。

- **同时写库不再丢轮：** 几个对话连着排队、或后台任务和对话同时写时，以前可能抢同一个数据库连接，丢掉几轮；现在每个连接加了锁。在隔离的 Hermes v0.23.2 里用假模型量过：6 个对话同时各连发 8 句、每次 48 轮，0.1.0a9 六次分别丢 0、4、0、12、23、22 轮，0.1.0a10 跑了五次都是 0。
- **重新生成、`/retry`、压缩后又说同一句短话（「继续」）：** 以前新回答存不进去或整轮丢；现在新旧两对都在，旧的一个字不变。**重新生成、重发只认「关」：** 只有 Hermes 按同一个会话号、同一个轮次号重送同一句时，这样来的一句才不会把 `#yuanwei-mem`、「确认开启」、「确认删除」再算一次；它们没生效时，回复后面会说一句固定的话（有开的口令而窗口仍关着：「没有照它打开记忆读取或删除，请再发一条新消息」；作废了一次等确认的申请：「没有照它确认，等确认的那次申请已作废，请重新提出来，再照提示确认」）。**终端的 `/retry`、微信上这段对话里有过改口的 `/retry`、压缩换号以后的重发，轮次号会变，照一条新话处理（和 0.1.0a9 一样），那时这些口令会照新话生效。** 副作用：重新生成一句普通的话，也会作废助手在上一遍里登记的开或删除申请，需要重新申请。
- **开轮失败：** 这一句里有「别用记忆」而开轮出错时（技能命令里你打的字、带来源说明的也算），这一轮读取先停着，直到成功关或你明确打开（写一条 `#yuanwei-mem` 就行）；这一轮的回复后面会说「没能确认已关」，下一轮再说一遍；助手这时调关闭工具，回的也是「没能确认已关」，不会说已关。下一轮那句提醒只在标记还在、还是这个对话时说一次（关上了、你明确打开了、已经换到别的对话都不说）；没显示出去的旧提示会在你下一条消息处理之前收回。库打不开时第一句里的「别用记忆」也记得住。这个对话后来的一轮里助手调关闭工具，会真去关，关成了才解除。有两个标记分开：「开轮失败」那个由下一次登记成功的开轮清掉；「没确认已关」（读取停着）只在这几种情形清掉：成功的关、明确的 `#yuanwei-mem`（被设置挡住的不算）、「确认开启」真把窗口打开了、窗口本来就是关着时的下一条你发的话。这个标记只记在这个 Hermes 进程里、这个对话的同一个原委实例里：只有压缩换号、换工作区会跟着走；**原委实例会换（Hermes 重启、对话闲置久了、重新生成／撤回、`/retry`、`/undo`、`/branch`、换模型或改配置；同一个对话连着说话、隔十秒、切走再回来是同一个实例，2026-11-26 在隔离的 Hermes v0.23.2 桌面上量过），换了就不记得了，那时窗口还是开着**（`/branch` 出来的分支里也是开着的）。压缩换号时，提问卡里或助手没答完时发的「关」写失败，标记也会落在换了以后的那个对话上。
- **技能命令：** 桌面版和聊天平台（微信等）上，你发 `/技能名 你打的话`，原委记你打的那几个字和回复，不记技能的包装和正文。**光 `/技能名` 不带话，Hermes 不把这一轮交给原委，不记；终端、新终端界面里不记**；带 `@文件` 的不记；自动加载的技能不记。你打的字里有 `#yuanwei-nomem` 也会关。
- **带待办清单、答到一半自动压缩（部分修好）：** 宿主插的待办快照不再让整轮丢；开头那一行被压缩改写、或被宿主并进摘要时，只要 Hermes 说这一轮是你开的，原委存开头那句和回复（中途的话、提问卡回答不收，里面说的「别用记忆」也不认，备注 `opening_only:row_not_found`）。**长轮里开头行并进摘要、又分不出是不是你开的，仍可能丢。**
- **聊天平台（微信等）一对一里的来源说明：** 在上面提问卡那一节列的一对一私聊里，带三行来源说明的开头那句（比如 `/retry` 那种），说明不再存进库，只存你的话；机器人发的不记。这几种情况说明仍会跟你的话一起存（带账号编号）：不在那份名单上的聊天软件、Discord 服务器帖子和 Slack 多人私信、几份说明并在一起或认不得的、带图的那一轮；以前版本存进库的说明也不会去掉。
- **宿主自己开的轮（后台完成、子代理跑完、唤醒）：** Hermes 说是它开的，就整轮不存：那一句不当成你的话，助手在这一轮的汇报（比如子代理查回来的结论）也不存（压缩以后也不会误记）。目标接着干、心跳到点、`/goal resume` 这几种宿主自己拼的轮，分不清是谁开的，照 0.1.0a9 的老办法记。
- **分支里的记忆开关：** 见上面「记忆读取的开关」一段；不带历史的分支（比如 `/rewind fork 1`）、或分支那一刻没有任何对话关着的，仍然是开着。
- **没修／已知：** Hermes 往你这句话里加的东西仍算成你的话：你附上或用 `@文件`、`@网址` 这类引用拉进来的内容（桌面版通常是整份文件）、聊天软件上 Hermes 给文件、图片、语音、引用加的说明（可能带本机文件路径）、`/plan` 等计划类命令里 Hermes 加的说明；终端里 `/loop` 的自动触发、心跳到点是不带机器标记的普通用户行，**照 0.1.0a9 会当成你的话存下**（分不出来；只有「技能命令」在终端里不记）；目标接着干（`/goal`）、心跳、`/goal resume` 的轮次照今天记（分不出是谁开的）；机器唤醒的长轮里的某些压缩情形；快捷命令别名（`quick_commands`）预先写好的参数会当成你打的字（分不出来）；数据库忙、那一轮还在待补文件里时重新生成，第二句可能进复核文件；上一轮还没配上就重新生成，新回答仍可能丢；事件重送得到旧令牌时，窗口层重放的是当时存的回执（和 0.1.0a9 一样，可能和现在的状态不符）；你自己用 `[` 开头的话、飞书会议邀请、聊天平台里来源说明认不得的（几份并在一起、不在一对一白名单里的平台、机器人发的），在待办快照行、开头行找不到这两种少见情形里照 0.1.0a9 不记；开头行没找到的那一轮里，中途打的「关」认不出；来源说明后面的「关」只认一份说明、白名单里的一对一；助手在几次工具调用之间说的话不存，只存最终回复；Hermes 自己接在回复后面的提示（比如写文件失败、到了上限）会当成助手的话存下。
- **要 Hermes v0.23.2：** 技能命令记你打的字（包括在那里写的 `#yuanwei-nomem`）、认出 Hermes 自己开的轮、带待办被压缩的长轮，这三样都要先问 Hermes「这一轮是谁开的」，这个接口只在 Hermes v0.23.2 上核过。更老的、没有这个接口的 Hermes 上，这几样不起作用，照 0.1.0a9 的做法。
- **体检：** `yuanwei doctor hermes` 新加一项 `turn_origin`，只报 Hermes 里「谁开的这一轮」那几处接口在不在，不影响别的结果；这一项的状态总是 ok，缺什么写在说明里。
- **测试：** 这批先在假宿主上测过（Hermes 源码片段逐字冻结在测试里，另有和 0.1.0a9 逐字节对照的测试）；2026-11-26 又在同一套隔离的 Hermes v0.23.2（假模型、断网，走桌面版用的网关和微信接口）上回归过：和 0.1.0a9 共有的 175 个场景逐个比，没有一处退步，另 5 个 0.1.0a10 专门的场景全对；之后在作者的一台 Mac 上用桌面版日用了一天（第二天又在微信上补测了两句），没丢轮。这批改动没在终端、新终端界面上跑过，Telegram、Discord、Slack 等别的聊天平台也没在真机上试过。

### 删掉一段对话、密钥不进记忆（11-10 起）

- **删一段对话：** 跟助手说「把这段对话在原委里的记忆删掉」，助手会调 `window_delete` 申请，把一句固定提示转告你；你**整条回复「确认删除」**才删（别的话、带引号、带第二行的都不算）。也可以用命令：`yuanwei conversations list hermes`、`yuanwei conversations delete hermes <编号>`（加 `--yes` 才真删；不给 `--db` 就用 Hermes 接头的库——从 `<hermes 家目录>/yuanwei/config.json` 读，输出里 `db_source` 写明用的是哪个库；库在别处就加 `--db <库>`，Hermes 家目录不在默认位置就加 `--hermes-home`）。删的是这个窗口（压缩前后都算）在原委里记下的原话和整理，**删了找不回来**，别的对话的原话不动；从这个窗口分叉出去的对话里，分叉之前那段属于这个窗口，也会一起删掉。确认那一轮不记，之后照常记。
- **删不掉的：** Hermes 自己的会话记录、你导出的文件、已经发给模型的内容、这一轮助手已经看到的内容、磁盘备份。**助手自己删不了只指对话里这组工具的约定**：能运行本机命令的助手照样能跑删除命令。Hermes 上不保证你回复前一定看到准确的范围提示（`yuanwei status hermes` 里的 `direct_display` 写明这台是靠助手转述还是程序直接显示）。
- **反过来也一样：** 在 Hermes 里删掉一段对话，原委里的原话和整理不会跟着删，以后仍然能搜到。要一起删，最好先在那段对话里跟助手说删、回「确认删除」，再去 Hermes 里删；已经在 Hermes 里删了的，用 `yuanwei conversations list hermes` 按开头预览找到编号，再 `yuanwei conversations delete hermes <编号> --yes`。在 Hermes 里重新生成、改一句再发、`/undo` 收回的那句话和回答，原委照样留着、不标哪份被换掉，以后查的时候会和别的话一样被找出来；现在没法只删其中一轮，只能整段删。
- **密钥：** 新存的对话在存之前先把认得出的 API 密钥、令牌、私钥、带密码的连接串、明确写出的密码遮掉（不进记忆，也不发给整理用的模型）；**认不出的格式可能会漏；密码本身是汉字、又没加引号的挡不住**（「密码是 abc123」「密码是「天王盖地虎」」能挡，「密码是天王盖地虎」挡不住）；以前存进库的旧数据只能用 `yuanwei secrets scan hermes` 看数（不给 `--db` 就用 Hermes 接头的库，输出里写明），不会自动改。

## 第三步：看状态

**查询超时：** 新配置默认等向量服务 10 秒；同一次 `recall` 中，完整向量身份相同的工作区共用同一句问话的向量，身份不同的分别算。超时后按安装采用的 `partial` 规则退回关键词，读取登记保留原因。原有配置写了 `timeout_query = 5` 的不会被自动改，状态会提示「查询超时设得偏紧，可以改成 10」。要自己调整，打开该机器人的 `<Hermes 家目录>/yuanwei/yuanwei.toml`（自选配置用安装时指定的文件），在已有的 `[embedding]` 段把这一行改成 `timeout_query = 10`，保存后重启 Hermes；不用改整理模型和密钥。

```
yuanwei status hermes
```

只读，什么都不改。会告诉你：装没装；插件文件有没有被改过；`memory.provider` 现在是不是原委；读取范围；本人登记（只说每个平台配了几个，不显示账号）；认得哪几个工作区、各记了多少条原话；整理用模型**今天和累计花了多少**（`cost`：所有工作区合计，按币种分开、不混加，日期按 UTC；`unrecorded_calls` 是「收到过模型回应、费用账里却没有这一步」的次数，正常是 0；`pending_rows` 是因为数据库忙暂存在库旁边文件里、还没补进库的行数）；以及插件实例运行以来记了几轮、**没记的轮次各是什么原因、各多少次**（`skipped`，比如 `not_owner`＝说话的不是本人、`owner_unknown`＝没登记或认不出作者、`workspace_unresolved`＝认不出工作区）。还有提问卡回答的累计数（`clarify`，见上面「助手提问卡里的回答」；`clarify_*` 不是没记的轮次）。

`relevance` 一项只读安装设置里的向量编码身份（不启动向量服务、不读向量、不读对话），写明相关度下限的状态：`keyword`（只用关键词，不涉及向量）、`calibrated`（已标定；说明里写「语义阈值已标定」或「沿用同模型文件的语义阈值；当前运行程序未实测」，后一种在 `basis` 里区分 `same_file_authorized_unmeasured` 和 `same_file_unlisted_runtime`，退出码不因它变成 1）、`uncalibrated`（未标定，只保留关键词命中，换了说法的内容暂时找不到，并提示回到推荐模型）、`invalid_identity`（缺少或不一致的向量身份，混合检索不能运行），以及这次没核到的 `not_installed`、`unconfirmed`（设置归属未确认）、`unavailable`（向量配置读不到）。其中 `uncalibrated`、`invalid_identity`、`unavailable` 会同时写进 `notes`。

`chat_owners` 另按平台显示漏登记提醒和未记数量。`chat_owners.skipped`（各平台行里的 `unregistered_skipped`）给出持久累计，插件运行时状态中同类字段叫 `owner_skips`：只数聊天平台因未登记、认不出作者或不是本人（`owner_unknown`／`not_owner`）而被挡下的事件，**不是所有没记消息的总数**，群聊和机器人拒绝不在这份累计里。它从启用这一实现后收到的事件起算，不回填旧消息，与上面的实例内 `skipped` 也不是同一份数。同一实例的重送不重复数，跨重启重送可能再数一次；登记后旧累计不会自动清零，也不会补存当时没记的话。计数文件只存平台名和整数，不存正文、账号、会话号或内容指纹；计数坏了或写不进会报问题，消息仍然不放行。

升级 Hermes 以后，先跑一遍：

```
yuanwei doctor hermes
yuanwei doctor hermes --hermes-home '<某个机器人的家目录>'
```

它会读 Hermes 的源码（只读），逐项核对原委依赖的接口有没有变，变了哪些、会影响哪些功能；还会给出目标家目录的 `chat_owners` 登记与计数提醒。`status hermes` 也接受同样的 `--hermes-home`。检查机器人档案时，默认仍从主安装目录找 Hermes 源码。输出里同样有 `relevance`（含义同上）。接口没变、没检测到漏登记、向量标定也没有缺口时退出码为 0；接口变化、检测到已配置的平台没登记、或相关度下限的状态是 `uncalibrated`／`invalid_identity`／`unavailable` 时为 1（所以只是向量没标定，也会返回 1，不只在宿主接口出问题时）；找不到源码目录时为 2。这不证明平台在线或实际消息已经能记下来，计数问题等其他提醒也要看输出。

## 第四步：卸

分三步，每一步都先能「只看不改」（不加 `--yes`：打印一份给人看的计划——会换掉哪个文件、撤回哪一行设置、会删什么、不删什么，最后一行写「这是计划，什么都没改；加 --yes 才执行」；要机器读的加 `--json`，其中「会不会改」叫 `would_change`）：

```
yuanwei uninstall hermes --yes                          # ① 插件换成空壳 ② 把 memory.provider 还原成装之前的值
（重启 Hermes）
yuanwei uninstall hermes --yes --host-reloaded          # ③ 确认 Hermes 已经重启，才删我们装的文件
```

**会删什么：** 只删我们装的三个文件、安装记录、运行状态文件；确认 Hermes 已重启后，也清掉原委自己的几个累计文件：未记计数（`owner-skips.json`）、跳过原因（`skip-reasons.json`）、提问卡回答的计数（`clarify-counts.json`）、内部错误（`internal-errors.json`），连同它们的 `.lock`。**不删你的记忆库**（`yuanwei.sqlite`）和工作区名字（`workspaces.json`），也不删 `config.yaml` 的备份和重装时留下的文件备份（`*.yuanwei-backup-<时间>`）——那是你的数据，要不要留由你定。你自己改过的插件文件不会被删，会告诉你。
如果你后来又把 `memory.provider` 改成了别的，卸载不会动它。
