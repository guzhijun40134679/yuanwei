# 装到 Hermes 上（预览版）

给用户看的一页：怎么装、怎么用、怎么看状态、怎么卸掉；每一步会改什么、怎么撤回。写的是预览版现状，2026-11-11 在 Hermes v0.22.0（+10397）上试装过，记录里列的各项都过了；没覆盖到的写在最后的限制里。装到你自己的 Hermes 上之前，会先问你。

## 先说四件事

1. **工作区只有两种：项目和「生活」。** 你在某个 Hermes 项目的文件夹里聊天，就记进那个项目；不在任何项目里的对话，都记进「生活」。Hermes 的机器人（配置档案，profile）每个有自己的记忆库，互不相干——但**新建的机器人要单独装一次**，见下面第 5 条。
   认不出这次对话属于哪个项目（**给了**当前目录但不合格、项目已经归档、项目表读不了）时，**这一轮不记也不查，不会偷偷记进「生活」**。
   **宿主没给当前目录**时（Hermes 的经典终端、新终端界面、桌面版聊天窗口建对话时都不传）：经典终端取 Hermes 进程此刻的工作目录来判项目；本机的桌面版、新终端界面（平台 `desktop`、`tui`、`local`）**问 Hermes「这一轮的文件夹」**来判项目（只管这几个本机入口；Telegram 等网关聊天平台不问，没传目录就照旧记进「生活」）——桌面版的对话走 Hermes 网关自己的会话管理，那条路建助手时不传目录（Hermes 上游问题 #144869），但这一轮进行时 Hermes 自己知道文件夹，原委用它的内部函数（`agent.runtime_cwd.scoped_session_cwd()`，取不到再取 `gateway.session_policy.active_policy().cwd`）取到。规矩：只在主对话里问；**绝不用进程目录**（网关是长期运行的进程，用它会把所有项目钉成同一个）；取到的值要展开 `~`、是绝对路径、本机上真有这个目录，否则当没取到；`~`（家目录）也按项目表判断，没有项目覆盖它时才归「生活」。这用的是 Hermes 的内部函数，不是写进插件接口的约定：Hermes 把两个都改名、或者都问不到（不在这一轮里），才退回记进「生活」（只剩一个来源时仍可能取到），插件照常工作；等 Hermes 上游修好 #144869，原委就直接用它传来的目录。取到、但不能用的值只记个数（`status` 里的 `host_cwd_dropped`），不记路径。宿主没给目录、后备也没取得有效目录时（取不到、是根目录 `/`、不是绝对路径），落进「生活」。给了目录的，判法不变。`yuanwei doctor hermes` 会核这两个内部函数还在不在：有任意一个就算正常（会写明哪个在、哪个不在；这只说明至少还有一个候选接口在，实际能不能取到值、作用域对不对，要另外核），两个都没有才报「变了」（桌面版会退回记进「生活」，不是致命错误）。`yuanwei status hermes` 里 `workspace.reason` 写着依据：`cwd_given`（宿主给了）、`cwd_from_process`（取了进程目录）、`cwd_from_host_turn`（问 Hermes 这一轮的文件夹取到的）、`no_cwd_life`（没目录，记进生活）。**这次没做：** 对话中途换项目文件夹时不再取一次（会话被挪进别的项目时 Hermes 会重建助手、原委重新初始化，走的是同一段代码）；本次验证针对普通桌面主会话；整理用的会话、`/btw`、`/bg` 这类旁支和辅助会话不在这一轮的范围里，不承诺统一落入「生活」。其中 `/btw` 的分支，Hermes 自己设了 `skip_memory=True`，原委不记，这是 Hermes 本来的设计。
   **恢复会话：** 启动时 `hermes --resume` 是 Hermes 先切到那个会话记的目录再启动插件，所以和新对话一样判；会话中 `/resume`，经典终端在下一轮开始时按进程目录重判一次（Hermes 在通知插件之后才切目录），宿主在通知里带了 `cwd` 就直接用；新终端界面、桌面版没目录就先问 Hermes 这一轮的文件夹，问不到才记进「生活」；压缩、分叉、新对话、撤销一概不重判。聊天平台恢复会话照旧说不清。
   **注意：读取范围选「甲」（每个工作区只翻自己）时，宿主没给目录、后备也没取得有效目录的项目对话会落进「生活」，只翻得到「生活」里的话。**
2. **能翻哪些工作区（读取范围）默认是「乙」：在「生活」里能翻生活和所有项目，在项目里只翻这个项目自己。** 写入永远只写你当前所在的工作区。想要更严或更松，装的时候选：
   `--read-scope isolated`（甲：每个工作区只翻自己）、`--read-scope life_all`（乙，默认）、`--read-scope all_open`（丙：全部互通）。这个范围只听你的设置，模型在工具参数里写什么范围都不算。
   一次翻了好几个工作区时，每一段材料前都标明出自哪个项目或「生活」，开头一行写读了哪些，没读到的（超时、放不下）也会在最后说一句。
3. **只记你本人的话。** 本机终端里说的话就是你的。（新终端界面和桌面版如果带着登录身份——经 WS 登录的网页后台或桌面版，Hermes 把登录的 `user_id` 传进来——原委在 Hermes 进程里用 `gateway.owner_identity.host_owner_subject()` 取这台电脑主人的系统身份来比：**相等就是主人**，不用配（`status` 里依据写 `host_owner_login`）；不相等，和聊天平台一样要配 `--owner tui:账号`／`--owner desktop:账号`，没配不记（跳过原因 `login_identity_needs_owner`），配了对不上是 `not_owner`；这一版 Hermes 没有这个函数、或调用失败，就**没法验证**，不当主人（`login_identity_unverifiable`），这时只能先用不带登录身份的入口（经典终端），或等原委跟进。比较只在内存里做，身份的值不写进库、不打印。没带登录身份的入口不受影响。）从手机、聊天软件（Telegram 等）进来的，要你先告诉原委哪个账号是你：装的时候加 `--owner telegram:你的账号编号`（可以写多个）。
   **不配的话，聊天软件里的话一条都不会记，也不会让模型去翻记忆。** 群里别人的话、机器人的话、认不出是谁的话，也都不记。Hermes 自己的配对、白名单只说「谁能用机器人」，不算「谁是你」。
4. **Hermes 自带的记忆照常开着。** Hermes 自己有一份小笔记，记你的偏好和要点（设置里是 `memory.memory_enabled`、`memory.user_profile_enabled`，默认都开）。原委不关它，只占「外接记忆插件」那一个位置（Hermes 同一时间只能接一个）；两者并存：它的笔记每轮都在，原委存全部原话、按需去查。
   要知道两点：① **「别用记忆」的开关只管原委自己**，Hermes 自带的笔记照样会放进上下文；② 想让原委单独负责记忆，可以自己在 Hermes 的设置里把那两个开关关掉（原委不替你改）。Hermes 的「技能」和原委互不相干，Hermes 交给原委记录的对话里已经去掉了技能的包装文字。
5. **每个机器人一个库，新机器人要单独装一次；群聊和机器人之间互发的消息，这一版不记也不查。**
   - Hermes 新建机器人时，会把主 Hermes 的设置整份复制过去，原委也在里面。原委认得出这种「复制来的设置」（装的时候在 `config.json` 里记了它属于哪个家目录，插件启动时核对）：**不启用**，不读、不写、不交工具，也不会碰主 Hermes 的库；`yuanwei status hermes` 和插件状态里写 `copied_from_other_profile`，并告诉你怎么办。
   - **老的设置（这一版之前装的、没有记家目录）而且库放在自定义位置的**：原委没法确认它属于哪个档案，所以先不启用（状态写 `ownership_unconfirmed`，不是「确定复制来的」），免得悄悄用到别的档案的库。对那个家目录重新跑一次向导确认：要继续用那个库就加 `--db <库文件>`，要用自己的新库就不加（旧库不动）；确认时会登记当前家目录，之后才启用。库在标准位置（`<家目录>/yuanwei/yuanwei.sqlite`）或这个家目录自己的目录里的老设置，照常用。
   - 要让某个机器人用原委：对它的目录跑一次向导，例如 `yuanwei setup --hermes-home ~/.hermes/profiles/<机器人名>`（不指定目录、又有机器人时，向导会先问你装给哪一个）。计划里会写「这是给机器人 <名字> 装，它会有自己单独的一个库」；它的库、设置、状态都放在它自己的目录下；复制来的旧 `config.json` 先备份。
   - 如果新建机器人时连库文件也一起复制过去了（Hermes 的 `--clone` 会整个复制 `yuanwei/` 目录），那份库里带着主 Hermes 的对话。**原委默认不沿用它**：计划里写明「这个机器人目录里有一份从别处复制来的记忆库，不沿用，挪到 <原名>.copied-from-<来源>-<时间>」；你确认计划以后，才把库文件和它的附属文件（`-wal`、`-shm`、`.d` 目录等）挪到同目录的那个备份名（不删、权限照旧），机器人从空库开始；不要那份备份的话你自己删。
   - 这一版只管**你和某一个机器人的一对一**。群聊里机器人回话的那一轮（平台 `bot_room`）明确不记不查，配了 owners 也一样（原因 `group_room_not_supported`）；机器人之间互发的消息（带机器人作者标签）不记，也不让它查。想让它记住群里定的事，回到一对一里说一句。多人、多机器人的记忆放到上线以后重新设计。

## 第一步：装（安装向导）

需要 Python 3.11 以上（装包用的 Python 和 Hermes 自己用的 Python 可以不是同一个，只要版本够，装的时候会记下包的位置给插件和后台进程用）。预览版发布到 PyPI 以后：

推荐先给原委单独建一个环境，放在 `~/.yuanwei/venv`（和自带向量引擎的 `~/.yuanwei/engine/` 放在一处，不打架），后面的命令都写完整路径：

```
python3 -m venv ~/.yuanwei/venv
~/.yuanwei/venv/bin/pip install yuanwei
```

不想建环境，就用 `python3 -m pip install yuanwei`（不要直接写 `pip`：有的电脑上只有 `pip3`）。

发布之前，也可以用本地的安装包装（不联网也能装，缺什么会直接报出来，不会自己去下载）：

```
python3 -m venv ~/.yuanwei/venv
~/.yuanwei/venv/bin/pip install --no-index --no-deps yuanwei-0.1.0a2-py3-none-any.whl
```

**重装／升级：** 原委这一版的插件文件变了，再跑一遍向导，计划里会分「新放的文件」和「更新的文件」两类；已装的插件文件如果还是装的时候的样子（你没改过），就换成新的，换之前先各备份一份（`<原文件名>.yuanwei-backup-<时间>`，权限和原文件一样）；你改过的不覆盖，向导会拒绝并告诉你是哪个文件。设置文件 `config.json`、`yuanwei.toml` 同理。

然后在终端里跑向导，一路选下来：

```
~/.yuanwei/venv/bin/yuanwei setup
```

（`yuanwei` 不在系统路径里很正常，用完整路径就行；下面和装完的提示里的 `yuanwei …` 都是同一个意思，向导最后会把你这台电脑上的完整路径写出来。输入 `~/.yuanwei/venv/bin/yuanwei --help` 能看到给用户用的全部命令。）

向导会依次：检查环境（Python、Hermes、接口是否对得上）→ 选助手（现在只有 Hermes；Claude Code、Codex、Pi 是后续更新）→ **选预设** → 选整理用的供应商和模型 → 设整理用的密钥 → 选要不要开本机向量 → 读取范围和哪个账号是你 → **列出计划** → 你确认了才改东西。**确认之前什么都不改；任何一步输入 `q` 或按 Ctrl-C 都是取消，什么都不会改。**

**四个预设**（后面每一步按它给默认值，你也可以逐项改）：

| 预设 | 整理 | 检索 | 标签 |
|---|---|---|---|
| 推荐 | DeepSeek `deepseek-flash` | 关键词＋本机向量（要下载一个约 600 MB 的模型，计算都在你自己的电脑上） | 整理测过；向量：LM Studio 是测过的那一套，自带程序和它几乎一样、没过我们自己定的严格标准 |
| 轻量 | DeepSeek | 只用关键词，不下载任何东西（以后可以 `yuanwei vectors setup` 再开） | 整理测过；只用关键词的答题效果没测过 |
| 自选 | 自己选供应商和模型 | 自己选 | 没测过 |
| 全本机（实验） | 你电脑上的大模型 | 本机向量 | 实验：效果没测过，吃内存，对话不出电脑 |

**整理用的供应商：** DeepSeek（测过，默认）；OpenAI `gpt-6-luna`（试过：11-06 在旧故事上整理了两串，新故事没测；按美元记账）；月之暗面、阿里云百炼、智谱、硅基流动、OpenRouter 和「手填」是没测过的（整理的提示词只在 DeepSeek 上调过；地址未核，模型名要你自己填）。没有价格表的供应商，**原委的费用估算和每日预算上限对它不准、可能不起作用**，花了多少以对方平台上看到的为准。

**整理用的密钥：** 向导只报「有没有、来自哪里」（不显示、不打印它的值）。**已经有的话会问你「用它吗？[Y/n]」**：回 n 就另输一把（输入时不显示，存进原委的**全局**密钥文件，读的时候排在环境变量和 Hermes 设置文件前面；这个机器人要是自己单独设过密钥，那份还排在最前面，向导会提醒）——比如已有的那把是要作废的。从外面运行 `yuanwei status hermes` 时，环境变量里没有，会再看 Hermes 的 `.env` 里有没有这个**名字**（只看名字，不读值），有就写 `hermes_env_file`（Hermes 运行时会自己读它）。没有的话你可以：① 在向导里输入（输入时不显示，存进全局的 `~/.yuanwei/keys/<变量名>`，权限只有你能读；几个机器人共用这一份）；② 自己写进 Hermes 的设置文件 `~/.hermes/.env`（`DEEPSEEK_API_KEY=…`），或在启动 Hermes 的终端里 export；③ 以后再说。也可以单独运行 `yuanwei key set`（交互式、不显示，存全局）、`yuanwei key status`（只报来源，不显示密钥的值：真正会用到的是哪一份、来自哪里，再分别说全局文件和这个机器人自己的文件在不在、类型和权限对不对——这几项不代表里面的值合格；也看 Hermes 的 `.env` 里有没有这个名字）、`yuanwei key test`（用真正会用到的那一份；先问，再发一个最小的请求，花不到一分钱，只报「能用／不能用／没验成」）、`yuanwei key delete --yes`（删全局）。

**密钥全局一份，几个机器人共用；某个机器人要用别的，可以单独给它设：** `yuanwei key set --this-bot-only --hermes-home <那个机器人的家目录>`（`key delete --this-bot-only` 删这一份）。存全局以后，命令会列出它找到的、有自己单独密钥文件的机器人（能用的话会先用它，不用全局这把；实际用哪把看 `yuanwei key status`，对别的机器人要加它的 `--hermes-home`），并告诉你怎样删掉那份、好让它改用全局的。这个列表只查了主家目录、它下面的 `profiles/*` 和你给的 `--hermes-home`，没有查全。读的先后：**这个机器人自己的密钥文件 → 全局密钥文件 → 环境变量**（`status hermes`、`key status` 里再多看一眼 Hermes 的 `.env`）。只有装的时候写进配置的（向导装的都有）才会去看这两个文件；配置里没有的只看环境变量。这个系统没法把文件权限设成只有你能读的（不是 Mac／Linux 这类），不存密钥文件，也只认环境变量。已经装好的不用动：升级以后自动往全局找。全局目录可以用环境变量 `YUANWEI_KEY_DIR` 改：**只认绝对路径**（可以用 `~` 开头；写成相对路径会报错、原委不用它）。这个目录会被设成只有你能读（0700），请用专门放密钥的目录，不要填共享目录或项目根目录；你自己的终端和 Hermes 服务要用同一个设置，不然两边看到的不是同一份。

`key status`／`key test` 查的是「整理实际用的那一份」：装好了就按配置里记的密钥文件路径查；还没装就按装好以后的标准位置预览（输出里会写明是预览）；用 `--api-key-env` 指定了和配置里不一样的变量，会写明查的是你指定的变量、不是当前整理配置。`--this-bot-only` 只管标准位置，配置里记的是别处的自定义文件时，它不会动那份文件（命令会说明）。输出只报来源，不显示密钥的值。

**本机向量：** 向导检测本机有没有 Ollama、LM Studio（命令在不在、本机服务有没有响应）。有就问你用哪个；**模型不在本机时，问过你、你同意了才让它下载**（这两种方式是由你电脑上的 Ollama／LM Studio 去它们的官方模型库下，原委自己不下载；选下面的「自带向量引擎」则是原委自己下载，下载前同样先问你）；原委**不替你安装、不替你启动** Ollama 或 LM Studio，只告诉你去哪里装：Ollama https://ollama.com/download ，LM Studio https://lmstudio.ai 。装好后会核验：算几句测试的话，核对维度、确定性，记下编码身份；核验不过就不写任何配置。LM Studio 的身份尽量取强：模型文件的 SHA-256（`lms ls --json` 给的是相对路径，拼到模型目录上——`~/.lmstudio/settings.json` 里的 `downloadsFolder` 只读这一个键，没有就 `~/.lmstudio/models`，再兼容旧位置 `~/.cache/lm-studio/models`）、运行包版本（`lms runtime ls` 里带 ✓ 的那一行）、加载时的上下文长度（`lms ps --json` 里已加载的实例；取不到才退回模型的上限，并标明是上限）。哪一项取不到，身份标「弱」，装完会写出是哪一项；**「测过」按身份比对，分三档**（测过的身份：LM Studio 本机兼容接口、模型 `text-embedding-qwen3-embedding-0.6b`、模型文件 SHA-256 `06507c7b…c3e439`、加载上下文 2048、无前缀无模板、L2 归一化、维度 1024、运行包 `llama.cpp-mac-arm64-apple-metal-advsimd@2.53.0`）：全都一样才写「测过（和测过的设置完全一样）」；只有运行包版本不同写「同一个模型文件和设置；LM Studio 的引擎版本不同（测过的是 2.53.0，你的是 X），算出的向量可能有极小差别，这个版本没核过」；模型文件对不上、取不到（身份弱）、上下文或维度不同，写「没测过」并列出哪几项不同。计划里（核验前的预判）、装完的那一行、`yuanwei status hermes` 的 `vectors.tested_comparison`（`level`、`differs`、`text`）都按这三档写。别的运行方式（Ollama、自带引擎、手填）没有测过的身份，一律「没测过」。NumPy 要装在 **Hermes 实际导入包的那个 Python 环境**里（不是启动脚本里的 `#!/bin/sh`，也不是更新前留下的旧环境）：原委先问 Hermes 自己（`hermes --print-runtime-command`，读它真实的 `sys.path`），找到的环境还要核过——真的是 Python、版本 3.11 以上、和 Hermes 实际用的是同一套；找不到就直说，向量退回只用关键词，你可以用 `--hermes-python` 指一个。没有 NumPy 的话先把**完整的安装命令**列在计划里（那个环境没有 pip 时用 Hermes 自带的 uv：`<uv> pip install --python <环境>/bin/python 'numpy>=1.26'`），问你能不能装，不同意向量就关掉。**原委已经正式告诉 Hermes 它需要 NumPy**：插件文件 `plugin.yaml` 里声明了 `numpy>=1.26`（一律声明，不管开不开向量，只用关键词的人也会多装约 5 MB）。Hermes 重建自己的包环境时会按声明自动带上（按 Hermes 源码：下次启动或更新时发现环境和声明对不上就会重建；在 Hermes v0.22.0（+10397，2026.9.24）上已经在真机上确认过，重建两次，NumPy 都自己装上了；其他发行方式没验证）；上面那条命令是现在就装进当前环境。万一还是丢了（比如 Hermes 重建了环境、而声明还没生效），向量自动退回只用关键词（不会出错），再运行同一条命令就能装回；`yuanwei status hermes` 的 `numpy_in_hermes` 会告诉你现在有没有、插件里有没有声明、没有的话补装的命令是什么，并说明可能是 Hermes 重建了环境。以前装过的，重新运行一次向导，`plugin.yaml` 会列在「更新的文件」里（先备份），声明就进去了。向量服务默认只许本机地址；要用别处的服务必须加 `--allow-remote-embedding`，那样你的原话（切成句子）和每次查询都会发给它。

**自带向量引擎（推荐，现在只支持 Mac 的 M 系列）：** 原委替你准备 llama.cpp 官方发布的服务程序和 Qwen3-Embedding-0.6B 的 Q8 模型文件，放在 `~/.yuanwei/engine/`。**下载之前先问你、说清每样多大，你同意了才下**；下载来的文件先核对原委这一版钉住的校验码（SHA-256），对不上就删掉、不会运行；整个运行包的每个文件每次启动前都核一遍。你电脑上如果已经有同一个模型文件（比如 LM Studio 里下过的），只读地直接用它，不再下载，也不动它。向量程序只监听本机（127.0.0.1），用本次启动专用的随机凭据，不走代理、不跟跳转；它的原始输出一律丢弃、不落盘。它在用到的时候由后台小进程拉起，闲着 15 分钟自己退出；隔了很久再回来的第一次提问可能赶上它还没起来，这一次只用关键词（状态里写 `engine_starting`）。卸载原委时会问要不要一起删它（默认不删）；`yuanwei vectors remove-engine --yes` 也能删。**这一版钉住的是 llama.cpp 的 `b11701`（ggml-org 官方发布，2026-10-16；Mac M 系列的 tar.gz，程序约 12 MB，解开约 32 MB）和通义千问官方的 Qwen3-Embedding-0.6B Q8_0（约 610 MB，Hugging Face 或魔搭下载；官方文件和测过的是同一个文件，SHA-256 相同）。** 压缩包和运行包里的每个文件的大小、SHA-256、可不可执行、包内链接的目标，都在 2026-11-11 真机上核过并钉死在表里。**一致性（2026-11-11 真机核过）：测过的只有 LM Studio。** 自带程序用的是同一个模型文件，向量和 LM Studio 算的几乎一样（全量 11,588 句里 8 句略低于我们定的线，最低 0.9977，没有低于 0.995 的），但正式抽样（1,000 句）里有 2 句低于 0.999，没过我们自己定的严格标准，所以向导的计划、核验后的那一行、`yuanwei status hermes` 的 `vectors.tested_comparison`、`yuanwei vectors status` 的 `engine.installed.model_label` 都写「同一个模型文件；向量和 LM Studio 算的几乎一样（…），没过我们自己定的严格标准，所以不能当成和 LM Studio 那套完全一样」，不写「测过」、不写「一致」。这条结果只属于这一版引擎（b11701）、这个运行包和这套启动配方：换了任何一样，就回到「一致性还没在真机上核」。向导第 6 步仍然推荐自带（不用装别的软件，最方便）；想用测过的那一套就选 2) LM Studio。系统如果拦住这个程序，原委只告诉你情况和 Apple 自己的办法，不会去改系统的安全设置。

**向量是后台慢慢补算的：** 库里已有的原话要一条条算，算好之前「找」只用关键词，`yuanwei vectors status` 会写还差多少、最近一次失败的原因。向量服务没开、连不上时这一次只用关键词（状态里标出来），后台暂停并退避，恢复后自己接着补。编码身份（模型、量化、运行方式）变了，旧向量不再用，全部重算；服务自己变了（比如升级了 Ollama）会暂停并提示你 `yuanwei vectors setup --reverify`，不会悄悄全部重算。旧身份留下的向量用 `yuanwei vectors prune --yes` 清。

### 全参数写法（不问话，给脚本和助手用）

给了助手名就不问话；不加 `--yes` 只列计划（什么都不改）：

```
yuanwei setup --host hermes --preset light                            # 只列计划
yuanwei setup --host hermes --preset light --yes                      # 真的装
yuanwei setup --host hermes --preset recommended --vectors ollama --download-model --yes
yuanwei setup --host hermes --preset custom --provider openai-luna --api-key-env OPENAI_API_KEY --yes
yuanwei setup --host hermes --preset local --vectors none --provider-model <本机模型名> --yes
```

| 参数 | 含义 |
|---|---|
| `--host hermes` | 助手；只有 hermes |
| `--preset recommended｜light｜custom｜local` | 预设；不给＝light（推荐、全本机要同时给 `--vectors`） |
| `--provider`、`--provider-url`、`--provider-model`、`--provider-param 键=值` | 整理用的供应商；只发列出来的参数；非本机地址只许 https |
| `--api-key-env 变量名` | 密钥从哪个环境变量读。**参数写法里不收密钥本身**（参数会留在 shell 历史和进程列表里）；要存密钥请在你自己的终端里运行 `yuanwei key set` |
| `--vectors none｜llamacpp｜auto｜ollama｜lmstudio｜custom`、`--embedding-model`、`--embedding-url` | 向量。`llamacpp`＝自带引擎（现在只支持 Mac 的 M 系列；别的系统显示「暂不支持」，可以用 LM Studio 或 Ollama）；`auto`＝支持就自带、不支持就报错，不悄悄换别的 |
| `--download-model` | 同意下载计划里列出的全部东西（自带引擎：程序和模型；Ollama／LM Studio：向量模型）（**`--yes` 不等于同意下载**） |
| `--engine-dir`、`--engine-url`、`--model-url`、`--model-file` | 自带引擎放哪里（默认 `~/.yuanwei/engine`）；换程序／模型的下载位置（只许 https，校验码仍然是原委钉住的那一个）；用你自己的一个模型文件（SHA-256 对不上就拒绝） |
| `--install-numpy`、`--hermes-python` | 同意往 Hermes 实际用的 Python 环境里装 NumPy（装的命令计划里会写全）／指明装包环境的 Python（要和 Hermes 实际导入包的是同一套，对不上会拒绝） |
| `--allow-remote-embedding` | 允许向量服务在本机以外 |
| `--ignore-probe-failure` | 本机大模型的长输入探针没通过也照装（自己承担） |
| `--read-scope`、`--owner`、`--mode`、`--db`、`--config`、`--spawn`、`--replace-provider`、`--hermes-home`、`--hermes-cmd`、`--config-method` | 沿用原来的写法 |

现有的 `yuanwei setup hermes …`（不带任何新参数）行为不变：只装插件，不碰供应商和向量。

**全本机预设的长输入探针：** 本机大模型服务的默认上下文常常只有几千个词元，会在你不知情时把整理要读的很长的输入截掉。装之前会发一段很长的输入（暗号放在最前面），核它能不能原样复述；复述不出来就不装。

### 让助手来装

把 `让助手来装.md` 交给 Hermes，说「照这个装原委」。助手只能用上面「全参数写法」里的命令，先把计划原样给你看，你同意了才加 `--yes`；**密钥由你自己在终端里设，不要贴给助手**；助手不替你装 Ollama／LM Studio，不自己重启 Hermes。

### 单独装、改本机向量

```
yuanwei vectors setup [--vectors ollama|lmstudio|custom] [--yes]    # 以后再开向量／换模型
yuanwei vectors setup --reverify --yes                                # 服务变了以后重新核验、记新的编码身份
yuanwei vectors status [--check]                                      # 只读；--check 会去探一次本机服务
yuanwei vectors prune --yes                                           # 清旧编码身份留下的向量
```

如果 `memory.provider` 原来是别家（比如 honcho），它会拒绝并告诉你原值；确认要换，加 `--replace-provider`（原来的值会记下，卸载时还原）。

**它会改什么：**

- 在你的 Hermes 家目录（默认 `~/.hermes`，也可以用 `--hermes-home` 指）里放这些文件：`plugins/yuanwei/__init__.py`、`plugins/yuanwei/plugin.yaml`、`yuanwei/config.json`（你的读取范围、主人名单、记忆库位置），向导装的还有 `yuanwei/yuanwei.toml`（整理供应商、检索方式、本机向量；**里面没有密钥**，只有变量名和密钥文件的路径），再加一份安装记录 `yuanwei/install.json`。
- 改 `config.yaml` 里 **`memory.provider` 这一行**，改成 `yuanwei`。能用 Hermes 自己的命令（`hermes config set`）就用它改，没有才直接改这一行；**改之前先备份** `config.yaml`（备份文件叫 `config.yaml.yuanwei-backup-时间`）。
- 记忆库默认放在 `<hermes 家目录>/yuanwei/yuanwei.sqlite`（`--db` 可以改地方）。后台子进程的输出写在 `<库>.spawn.log`，`yuanwei status hermes` 里能看到最近几行（过了密钥过滤）。
- 选了「自带」向量引擎并同意以后，会在 `~/.yuanwei/engine/` 下放程序和模型（可用 `yuanwei vectors remove-engine` 删）。
- **不会**改 `CLAUDE.md`、`AGENTS.md`、`SOUL.md` 这类说明文件；**不会偷偷联网**（下载只在你同意之后：用 Ollama／LM Studio 时，是它们去下向量模型，原委自己不下；用自带向量引擎时，原委自己下载程序和模型；你同意往 Hermes 的 Python 里装 NumPy 时，会由 pip 或 uv 去下载；每一种都会先问你。你选了向量，原话才会发给你配置的向量服务；整理用的模型当然要联网，除非你选了全本机）。

**装好以后要重启 Hermes**，新的记忆提供者才会加载。装好以后看状态：`yuanwei status hermes`（里面有「整理供应商」「向量」两项），或 `yuanwei vectors status`。

**怎么撤回：** 见第四步；或者手动把备份的 `config.yaml` 放回去。卸载**不删**你的记忆库和密钥文件（要删全局密钥文件用 `yuanwei key delete --yes`，这个机器人自己单独的那份加 `--this-bot-only`）。

## 第二步：用

装好重启以后，平时就正常聊天，不用做别的：

- 每一轮**完成**的对话（你说的和助手最终回的），主人本人的才会被记进当前所在的工作区；被打断的轮次、机器人、定时任务、子代理的话不记。
- 默认**只给工具、不主动塞材料**：助手需要翻历史时自己调 `recall`（查记忆）、`get_messages`（按编号取原话）、`attachments`（看一条消息挂到哪里）、`status`。（这些工具能不能出现在助手的工具列表里，还取决于你 Hermes 的工具集设置，真机上没核过。）
- **记忆读取的开关是按「对话窗口」管的**（11-10 起）。一个窗口就是你和助手的这一段对话；压缩、重启不换窗口；`/new` 是新窗口；`/branch` 分出来的是一个新窗口，分出来那一刻是什么状态就复制什么状态，之后各管各的；`/undo` 不改开关。子代理、定时任务不能读，也不能开。
  - **关：** 说「别用记忆」这类话、在消息第一行写 `#yuanwei-nomem`、或者助手调关闭工具，**任何一样都关**。关了以后，这个窗口**每一轮**都不翻记忆（包括「便条」「目录」），直到你重新打开；助手每轮会收到一条回执，说明读取是关着的、怎么打开。
    **能保证的只有口令**（和设置里的开关）；大白话的「别用」靠助手听懂、再加上程序里的规则认出，**可靠度没量过**，认不出的会漏。这一版还补了几种说法（「不要和记忆核对」「我不希望你再用记忆」「不想让你看以前的对话」「现在不要查」「先不开」等），宁可多拒、不可漏拒，所以偶尔会多关（比如「用不用记忆都行」也会关）。
  - **开：只有两种办法。** ① 在消息第一行写 `#yuanwei-mem`；② 你要助手用记忆时，助手调开启工具申请，程序登记一条「待确认」，助手把一句固定的话转告你：「要在这个窗口重新使用长期记忆吗？回复「确认开启」即可。」你的**下一条消息**第一行正好是「确认开启」（前后空白和末尾的句号、感叹号可以有）才打开；下一条是别的话，待确认就作废，窗口仍然关着，要重新申请。助手不能替你确认。
  - **设置优先：** 如果你在设置里把这个会话或工作区的读取关了，说什么都打不开，也不会改你的设置。
  - 这一版只管「本插件之后的新读取」：已经交给模型的材料、Hermes 自己的上下文，开关抹不掉，回执也不会说「已撤回」。**Hermes 自带的那份笔记也不归这个开关管**（见开头第 4 件事）。
  - 关闭要写进窗口状态才算数。写失败时，回执会说「没能确认已关闭」，并且这个窗口先不读；不会报成「已关」。
  - 关着的窗口，在你关上、打开、恢复一个关着的窗口时，各提示一句（提示在回执或状态里给；Hermes 上能不能直接显示给你，**真机上没核过**）。
- 想换成「回答前先查一张便条」或「只在开头给一份主线目录」：装的时候加 `--mode note` 或 `--mode directory`（默认是 `tools_only`）。这两种也照上面的读取范围读，读多个工作区时一样逐段标明出处。

### 删掉一段对话、密钥不进记忆（11-10 起）

- **删一段对话：** 跟助手说「把这段对话在原委里的记忆删掉」，助手会调 `window_delete` 申请，把一句固定提示转告你；你**整条回复「确认删除」**才删（别的话、带引号、带第二行的都不算）。也可以用命令：`yuanwei conversations list hermes`、`yuanwei conversations delete hermes <编号>`（加 `--yes` 才真删；不给 `--db` 就用 Hermes 接头的库——从 `<hermes 家目录>/yuanwei/config.json` 读，输出里 `db_source` 写明用的是哪个库；库在别处就加 `--db <库>`，Hermes 家目录不在默认位置就加 `--hermes-home`）。删的是这个窗口（压缩前后都算）在原委里记下的原话和整理，**删了找不回来**，别的对话的原话不动；从这个窗口分叉出去的对话里，分叉之前那段属于这个窗口，也会一起删掉。确认那一轮不记，之后照常记。
- **删不掉的：** Hermes 自己的会话记录、你导出的文件、已经发给模型的内容、这一轮助手已经看到的内容、磁盘备份。**助手自己删不了只指对话里这组工具的约定**：能运行本机命令的助手照样能跑删除命令。Hermes 上不保证你回复前一定看到准确的范围提示（`yuanwei status hermes` 里的 `direct_display` 写明这台是靠助手转述还是程序直接显示）。
- **密钥：** 新存的对话在存之前先把认得出的 API 密钥、令牌、私钥、带密码的连接串、明确写出的密码遮掉（不进记忆，也不发给整理用的模型）；**认不出的格式可能会漏；中文写的密码挡不住**；以前存进库的旧数据只能用 `yuanwei secrets scan hermes` 看数（不给 `--db` 就用 Hermes 接头的库，输出里写明），不会自动改。

## 第三步：看状态

```
yuanwei status hermes
```

只读，什么都不改。会告诉你：装没装；插件文件有没有被改过；`memory.provider` 现在是不是原委；读取范围；主人名单（只说每个平台配了几个，不显示账号）；认得哪几个工作区、各记了多少条原话；整理用模型**今天和累计花了多少**（`cost`：所有工作区合计，按币种分开、不混加，日期按 UTC；`unrecorded_calls` 是「收到过模型回应、费用账里却没有这一步」的次数，正常是 0；`pending_rows` 是因为数据库忙暂存在库旁边文件里、还没补进库的行数）；以及运行以来记了几轮、**没记的轮次各是什么原因、各多少次**（比如 `not_owner`＝说话的不是主人、`owner_unknown`＝没配主人、`workspace_unresolved`＝认不出工作区）。

升级 Hermes 以后，先跑一遍：

```
yuanwei doctor hermes
```

它会读 Hermes 的源码（只读），逐项核对原委依赖的接口有没有变，变了哪些、会影响哪些功能。没变就全是「对」。

## 第四步：卸

分三步，每一步都先能「只看不改」（不加 `--yes`：打印一份给人看的计划——会换掉哪个文件、撤回哪一行设置、会删什么、不删什么，最后一行写「这是计划，什么都没改；加 --yes 才执行」；要机器读的加 `--json`，其中「会不会改」叫 `would_change`）：

```
yuanwei uninstall hermes --yes                          # ① 插件换成空壳 ② 把 memory.provider 还原成装之前的值
（重启 Hermes）
yuanwei uninstall hermes --yes --host-reloaded          # ③ 确认 Hermes 已经重启，才删我们装的文件
```

**会删什么：** 只删我们装的三个文件、安装记录、运行状态文件。**不删你的记忆库**（`yuanwei.sqlite`）和工作区名字（`workspaces.json`），也不删 `config.yaml` 的备份和重装时留下的文件备份（`*.yuanwei-backup-<时间>`）——那是你的数据，要不要留由你定。你自己改过的插件文件不会被删，会告诉你。
如果你后来又把 `memory.provider` 改成了别的，卸载不会动它。

## 没做、没核的

- **只在 Mac 上测过**（M 系列芯片的 macOS）。Windows、Linux 没测过。Windows 上已知可能出问题：同时写库时的文件锁不起作用、命令行输出可能乱码或报错、整理时可能闪出黑色窗口；要等用真的 Windows 电脑测过再修。向导在 Mac 以外的系统上会先提醒一句（交互的第 1 步和只列计划的输出里都有）。
- 真的 Hermes 只试装过一次：2026-11-11，v0.22.0（+10397），经典终端的各项检查都过了，桌面版能记能查；别的 Hermes 版本、别的系统、别的聊天入口没有试过，Hermes 以后更新也可能让某一项对不上（`yuanwei doctor hermes` 会核几处）。
- 2026-11-11 的试装里真机核过的：DeepSeek 整理（地址、模型名、费用记账）、LM Studio 的本机兼容接口和模型（编码身份、模型文件 SHA-256）、找 Hermes 实际用的 Python 环境并用 Hermes 自带的 uv 装 NumPy、自带向量引擎的下载和启停。**没在真机上核过的**：除 DeepSeek 以外的各家供应商的地址和模型名、Ollama 的模型名和下载命令、`gpt-6-luna` 的价格、向导里写的各家官方网址；这些照旧标「没测过」。机器人（profile）的隔离 2026-11-11 在真机上核过：新建机器人带过去的设置不启用，对它单独装以后写它自己的库。群聊不记不查只在假宿主上测过，没在真的 Hermes 群聊里跑过。
- 整理用的密钥在 Hermes 进程里到底看不看得到，要装完用 `yuanwei status hermes`（和插件自己的状态里的 `organizer_key`）核；多分身复用（`gateway.multiplex_profiles`）的部署下，各分身的 `.env` 不会并进环境变量，那样用原委的全局密钥文件（`yuanwei key set`）就行，几个分身共用一份；要单独的再加 `--this-bot-only`。
- 各聊天平台上「账号编号」是不是稳定等于账号，没有逐个平台核；你配 `--owner` 前请先确认编号对不对。
