# 开发说明

给改代码、写接头的人看。给用户看的说明在 `README.md`（英文）、`README.zh-CN.md`（中文）和 `docs/装到Hermes上.md`。

- **默认是「只给工具」**：模型要查时自己调 `recall`／`get_messages`／`attachments`，不在每轮自动塞材料。可选的模式还有「固定提醒」「便条」「目录」（`--mode`），见 `docs/产品规则表.md` 第 9 节。
- 基础包只用 Python 标准库；向量检索要 NumPy 和一个向量服务：用户自备的兼容 `/v1/embeddings` 的本机服务，或「自带」的 llama.cpp 服务程序（`enginepkg.py` 准备、`enginerun.py` 看管；安装向导会问）；MCP 服务要可选依赖 `mcp`。
- 默认写入提示词是 B0（只改规则），现行 A 留开关（`write_prompt = "A"`）。
- 命令行：`yuanwei --db notes.sqlite --workspace proj record ...`；Python：`from yuanwei import Memory`。

## 已入库的原话不等整理就能查到

- **能保证的：** 已经成功入库的原话（`record` 回执 `raw_saved=True`、`readable=True`），不等封步、不等整理，就能用关键词检索和按编号读到；整理失败、放弃、预算暂停、整理卡住都不影响。整理只是让它更好找（主线、回、同回补料）。
- **混合模式和向量：** 新入库的原话由后台补算向量（`yuanwei vectors backfill`）。缺向量时看 `vector_fallback`：库默认 `strict`（缺一条整次报缺 `missing_vector`，研究装置用）；安装向导写 `partial`（有向量的走关键词＋向量，没算好的只靠关键词，并登记）。细则见 `docs/产品规则表.md` 第 10 节。
- **不在保证里：** 宿主没有交给 `record` 的话；还在本机待补文件里的话（回执 `pending=True`、`readable=False`）。
- **不是召回率保证：** 能被搜到不等于每次都会被召回，排序、额度照旧有边界。
- 读取范围（截点）新格式记原话上界 `raw_seq` 和整理上界 `org_seq`；旧格式 `{vclock, org_seq}` 照旧读。当前这一轮自己的话由接头绑定后排除，不当历史交回来；没有轮次上下文的离线接口不做这件事。细则见 `docs/产品规则表.md` 第 10 节。

## 接口注意（给第二段接头的人）

- `current_turn`（最近声明的轮次和会话）每个工作区只有一行；调用省略 `turn_id`／`session_id` 时回退到它。**它只是低层可信调用、单个活动上下文时的便利，不能当多会话的安全绑定，也不能直接暴露给模型。** 第二段由接头在每次工具调用时显式给工作区、会话、分支、轮次；缺失或对不上就拒绝，不采信模型自己填的身份或 `history_allowed`。
- 核心以 `status="refused"`、`reason` 表示拒绝，并附按原因生成的中性文字（`refusal_text`，返回里还有 `text` 等字段）；按时点分的完整回执在第二段接头落地。
- `ask`、`answer_request`、`export` 是可信的本地接口，不是受保护的模型工具，不能作为读取权限的旁路暴露给模型。

## 待补文件（数据库一时写不进去的原话）

- 数据库忙时，`record` 把原话写进本机待补文件，下次打开、记录或显式补写时按顺序补进库。有更早的待补时，新原话不会抢在前面入库：「有没有更早的待补」的检查和直接入库在同一把追加锁里做，领取和追加用同一把锁。没有积压时同时记录的几个进程会在锁上一个一个入库，不会因此被排进待补。非 POSIX 系统没有进程间文件锁，这条保序没有验证。
- 一次补写返回 `done`，只说明这一次领取的批次补完了，**不等于待补已全部清零**；补写期间或之后排进来的，要等下一次打开、记录或显式补写。
- 程序没能接收的项（内容冲突、读不出的行、校验错误等）原样挪进 `.review` 待核文件：原行（解不开的存成 base64，不丢字节）、原异常和时间，需要人去核查；`IntegrityError`、`DataError` 只是程序的分类，不等于原话本身有错。待核的项不再自动重试。`status()["pending_review"]` 数的是待核文件的**行数**；中断以后同一项可能记两行，所以它不是去重后的问题数。
- 补写时的临时文件（`.tmp`）可能残留，不参与补写，也不挡恢复。
- 直接入库期间一直占着追加锁。数据库忙时，一次入库最多重试 5 次，每次 SQLite 自己还要等最多 3 秒，所以单次入库可能等到将近 18 秒，这还没算维护和调度。
- **故障降级不保证顺序**：如果追加锁打不开，新原话会不加锁排队；如果待补文件也一直写不进去，就直接写库。这两种情况都不保证顺序。回执里带 `flush_errors` 时，要当作故障降级处理，不能当成一次正常的保序记录。

## 第二段：显式绑定、固定口令、四种模式、MCP 服务（接头的底层）

- **MCP 是可选依赖**（官方 Python SDK `mcp`，MIT；`pip install yuanwei[mcp]`），基础包不依赖它。启动：`python -m yuanwei.mcp --db notes.sqlite --workspace proj --host pi`（工作区、宿主、上限都来自启动参数，工具参数换不了）。四个工具：`recall`（可选关键词）、`get_messages`、`attachments`、`status`；不开放 `remember`，`ask`／`answer_request`／`export` 不进 MCP。
- **读取工具开放不开放，看这家宿主有没有可信的身份链**：目前只有 Hermes（同进程插件）和 Pi（扩展给每个会话单起 MCP 进程并带连接句柄）有「候选」链，**都只用假事件核过，没有在真机上验证**；Claude Code 和 Codex 的静态 stdio 登记拿不到会话身份，`tools/list` 只有 `status`，写明「暂不支持读取」。详见交回报告和 `身份链设计-甲.md`。
- **`Access`（`yuanwei.access`）** 是绑定层：接头在宿主的可信事件上调 `begin_turn`（解析固定口令 `#yuanwei-nomem`／`#yuanwei-mem`，只认第一物理行；窗口级的开关见 `docs/产品规则表.md` 第 11 节）、`inherit_turn`、`close_turn`、`register_connection`；读取方调 `start_read`／`finish_read`。**第一段的 `current_turn` 不是安全绑定，绑定路径不认它。**
- 规则和边界见 `docs/产品规则表.md` 第 6–9 节。回执的第二种措辞（「此前已有材料交入本轮」）现在一个宿主都出不了：交付规则没在固定版本的真机上验证。
- 测试环境（2026-11-09）：Python 3.14.3、mcp 1.28.1、anyio 4.14.2、pydantic 2.13.4、numpy 2.4.4、pytest 9.0.3；全部在断网沙箱里跑。

## Hermes 接头

**给用户看的完整说明：`docs/装到Hermes上.md`**（装、用、看状态、卸载四步，每步改什么、怎么撤回）。看状态：`yuanwei status hermes`（只读：装没装、读取范围、认得的工作区、没记的轮次各是什么原因）。

- 装：推荐用向导 `yuanwei setup`；老写法 `yuanwei setup hermes`（只装插件，不碰供应商和向量）照旧可用。都是先列计划，加 `--yes` 才改。库默认放在这个 Hermes 分身的家目录里（`<hermes_home>/yuanwei/yuanwei.sqlite`），不用自己起名字；`--db` 可以改地方。有 `hermes config set` 就用它改 `memory.provider`，没有才逐行改；原来是别家要加 `--replace-provider`。装好后重启 Hermes。
- **工作区只有两种：项目和「生活」**。在某个 Hermes 项目的文件夹里聊天，记进那个项目；不在任何项目里的对话都记进「生活」。机器人（profile）每个有自己的家目录和库；新建机器人复制来的设置会被认出来、不启用，要单独装一次；群聊（`bot_room`）和机器人互发不记不查（见产品规则表第 19 节）。项目靠当前工作目录对着 Hermes 的项目表认；认不出是哪个项目（给了不合格的目录、项目已归档、项目表读不了）这一轮就不记也不读，不会偷偷记进「生活」；宿主没给工作目录时：经典终端取 Hermes 进程的目录，新终端界面和桌面版记进「生活」（见产品规则表第 17 节）。写入永远只写当前所在的工作区。
- **能翻哪些工作区（读取范围）**：默认 **乙**——在「生活」里能翻「生活」和所有项目，在项目里只翻这个项目自己。可选：`--read-scope isolated`（甲，每个工作区只翻自己）、`--read-scope all_open`（丙，全部互通）。范围只听你的设置，模型在工具参数里填什么范围都不算。翻多个工作区时，每一段材料都标明出自哪个项目或「生活」，开头一行写读了哪些。
- **只记你本人的话**：本机终端里说的话就是你的。聊天平台（Telegram 等）要告诉原委哪个账号是你：`--owner telegram:123456`（可重复）；没配、或者发言的不是你（群里别人、机器人），就不记、也不翻。Hermes 的配对和白名单只说「谁能用机器人」，不算「谁是你」。宿主没说清这是不是主对话时也不记。
- 卸：`yuanwei uninstall hermes --yes`（空壳 → 撤设置 → 确认 Hermes 重启后加 `--host-reloaded` 才删文件）。
- 便条、目录模式（`--mode note`／`--mode directory`）和读取工具一样照读取范围读，读多个工作区时逐段标明出处、开头一行写读了哪些。
- 升级 Hermes 以后先跑：`yuanwei doctor hermes`（读本机 Hermes 源码，只读），看哪项变了、影响哪些功能。依赖清单在 `src/yuanwei/hermes_compat.py`，三版对照在兼容表第 10 节。
- 接头只 import Hermes 公开的 `MemoryProvider` 基类；按功能探测，对不上的功能自己关掉，Hermes 照常起。2026-11-11 在 Hermes v0.22.0（+10397）上真机试装过一次，只覆盖当时记录里列的项目；适配器会懒导入的几个内部模块见 `hermes_compat.py` 的清单。
- Hermes 自带的内置记忆照常开着，原委只占外接插件那一个位置；见 `docs/产品规则表.md` 第 15 节。
