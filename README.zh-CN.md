# 原委 Yuanwei

[English](https://github.com/guzhijun40134679/yuanwei/blob/main/README.md) | 简体中文

**事有原委，话有出处。** 给 AI 助手的长期记忆。

网站：https://yuanwei.dev

> 预览版 · 研究原型，部分功能还在开发和测试中。2026-11-11 在 Hermes v0.22.0（+10397）上试装过，记录里列的各项都过了；没覆盖到的写在限制里。0.1.0a10 又在隔离的 Hermes v0.23.2 上用假模型、断网回归过（约 180 个场景，走桌面版用的网关和 Hermes 的微信接口，和 0.1.0a9 比没有退步），并在作者的一台 Mac 上用桌面版日用了一天（第二天又在微信上补测了两句），没丢轮；Telegram、Discord、Slack 等别的聊天平台没在真机上试过。

## 它做什么

- **原话原样存。** 你和助手说过的话原样存下，记着是谁说的、哪天说的。不改写，不总结。
- **按事归好。** 写入时只做一件小事：把每句话挂到哪件事、哪一回，加一句摘要。同一件事的话归在一起，同类不同次的分开。
- **翻原话回答。** 助手要用到以前的事，先查原话，同一件事的先查，每句带日期交给助手，由助手对着日期理清新旧。
- **新话不必等整理。** 已入库的原话可立即按关键词查；向量还没算好时，安装默认仍走关键词，算好后也按向量。`recall` 和便条只排当前这一轮，同一会话里更早的话（整理过的、没整理的）都能查到。结果说明会列出未整理的消息编号，原话正文不加字。
- **带图的轮次也保存。** 保存用户打的字和助手回答，另记图片张数；只有图时也保存图片张数和回答。图片与宿主附加的缓存路径不保存；Hermes 在纯图时自动补上的英文提问可能一并保留，因为接口无法与用户逐字输入区分。
- **你在助手提问卡里的回答也保存。** 在你自己的电脑上，或原委照 Hermes v0.23.2 源码核过的一对一会话里（微信、Telegram、Discord 的私聊，Hermes 在会话授权下的 API 会话，Slack 的一对一私信），助手用提问卡（Hermes 的 `clarify` 工具）问你，你点的、打的回答会接在你这一轮的话后面，一行一条、带标签：助手问的题、给的选项、你是点选还是自己写的。没答、跳过的题不存。提问卡里的回答和你直接发的话一样：只有写成认得出的样子的密钥和密码（`sk-…`、`XXX_KEY=…`、「密码是 …」、`password=…`）会被挡掉；在提问卡里只打一个密码，会照打的存。共用的会话（Discord 服务器里的帖子、Slack 多人私信）里的提问卡回答不存，因为谁都可能答了；原委还没核过的聊天软件（WhatsApp、Signal、Matrix、飞书、邮件等）里，哪怕是一对一，现在也还不存。在 Telegram 这类平台上，一道带选项的题，你没先点「✏️ 其他（输入回答）」就直接打字，卡片会取消，Hermes 把打的字当成中途的话：0.1.0a9 起原委把这句按中途的话存（见下一条，不算卡片的回答），已点好的回答也存（只在假宿主上测过，没在真机核过）；打选项的编号或选项原文算点选。想在卡片里自己写，先点「其他」。
- **助手没答完时你又发的话也保存。** 助手还在答，你又发了一句（Hermes 把它当成更正、接着往下答的叫「改口」，插在工具结果后面的叫「插话」），这一句会接在你这一轮的话后面，一行一条、按发生的先后、带标签：`（用户中途又说）`＝改口，以及聊天平台上原委认得出 Hermes 加的来源说明的插话；`（中途插入·来源未核实）`＝来源没法核实的插话。桌面版里嵌的预览页，脚本不用你点也能在助手忙时发一句，原委分不出这和你自己打的有什么不同，所以你自己电脑上的插话一律标「来源未核实」；可见按钮和插件替你发的，和你打的一样存。这样发的「别用记忆」会关上窗口（来源未核实的也算）；这样发的「确认删除」「确认开启」和 `#yuanwei-mem` 不算数，下一轮会说一声。收不到的：你按了「停止」的轮次（Hermes 不交）、这一轮还没有工具结果时的插话（Hermes 把它插到这一轮开头那句的前面）、没赶上这一轮的插话（变成下一轮的开头，聊天平台上连来源说明一起，这是已有的问题）、Codex app-server 运行时的改口。原委认不清这句话属于哪一轮时，只存开头那句和回复，中途的话一条不收。这类话和提问卡回答一样只在一对一里收：共用的会话、原委还没核过的聊天软件（哪怕是一对一）里，有这类话的轮次不存（有一种少见情形只存开头那句和回复）。助手的 `status` 工具现在也会说这个会话开始几轮、记下几轮、没记几轮。已知限制见 [`docs/装到Hermes上.md`](https://github.com/guzhijun40134679/yuanwei/blob/main/docs/装到Hermes上.md)；这一条最初只在假宿主上测过。2026-11-25 在隔离的真 Hermes v0.23.2 上（假模型、断网）跑过一次逐功能清点，找出的问题 0.1.0a10 修了一批（同上那页「0.1.0a10」一节），之后在同一套环境上重跑过约 180 个场景，和 0.1.0a9 比没有退步；Telegram、Discord、Slack 等别的聊天平台没在真机上试过。
- **名次靠前的先交。** 查到的材料按检索名次分页，每页里再按时间排；命中及它带出的上下文放在同一页。跨工作区按各区的本地名次轮流装页，各段标明出处。单组大到一页装不下时明确报错，不悄悄拆开或丢掉。
- **一次查询默认交约 8,000 词元，要多可到 24,000。** 不带额度的一次查询总共选约 8,000 估算词元（中英文按同一把尺子量）；助手主动要更大的额度，上限是 24,000。单条消息太长、默认额度装不下时，会自动放宽到 24,000 再试一次；还装不下就明说「找到了相关内容，但这条消息太长放不进额度」，不会说成没有找到。
- **查不到就不硬塞。** 一条原话要进候选，得有关键词命中；开了本机向量、且这个向量模型已标定的，意思足够接近也行（余弦分数不低于为这个模型量出来的下限）。没有任何一条够格，就返回「没有找到相关记录」，不附材料，也不给续读提示。每条原话都标明是怎么找到的：关键词命中、仅意思相近（带余弦分数）、还是附带的邻近或同一回的原话。原话不改写。

底子是检索原话（也就是常说的 RAG：关键词，加上可选的本机向量），上面加了一层很轻的按事整理。整理只用来帮着找，交给助手的始终是原话。

## 为什么存原话

很多记忆产品的做法，是把对话总结成摘要，或者抽成几条事实再存。我们反过来：原话原样存，整理只当目录。

- **总结一错，后面就跟着错**，还查不出是哪句话说的。原话带着日期，对不对你自己能核。
- **公开研究里也有类似的发现。** LongMemEval 的论文比较过：用摘要或抽出来的事实去代替原话交给模型，答对率会降，跨会话汇总的题是例外；反过来，把抽出来的事实只用来帮着检索、交出去的仍是原话，召回和答对率都提高了。
- **检索原话这条路还远没挖到头。** 我们自己的测试里，原话检索加一层轻整理，和 Mem0 打平；但每道题真正需要的原话一般只有两三句，我们交给模型的却有几百句。怎么找得更全、交得更准，是接下来要做的。

## 安装

需要 Python 3.11 以上，以及已经装好的 Hermes。

推荐先给原委单独建一个环境，放在 `~/.yuanwei/venv`（和自带向量引擎的 `~/.yuanwei/engine/` 放在一处，不和别的东西打架）。后面的命令都写完整路径，不用你把 `yuanwei` 加进系统路径：

```
python3 -m venv ~/.yuanwei/venv
~/.yuanwei/venv/bin/pip install yuanwei
~/.yuanwei/venv/bin/yuanwei setup
```

不想建环境也行，用 `python3 -m pip install yuanwei`（不要直接写 `pip`：有的电脑上只有 `pip3`）；装完 `yuanwei` 在哪，向导最后会把完整路径写给你。

`yuanwei setup` 是一问一答的向导：检查环境 → 选预设 → 选整理用的模型（也可以选「不整理」：不用密钥、不花钱，原话照常存和查；以后 `yuanwei organize on --yes` 再打开）→ 设密钥（输入时不显示；存在你电脑上只有你能读的一个文件里，几个机器人共用）→ 选要不要开本机向量 → 选读取范围、按检测到的聊天平台逐个登记本人账号（可跳过；未登记的平台不会记）→ 列出计划 → 你确认了才改。平台检测只看配置，不能证明平台在线，也可能漏掉；已知平台可以手动登记。

| 预设 | 整理 | 检索 |
|---|---|---|
| 推荐 | DeepSeek（整理测过） | 关键词＋本机向量（要下载约 600 MB 的模型，问过你才下载；向量：LM Studio 是测过的那一套，自带程序和它几乎一样、没过我们自己定的严格标准） |
| 轻量 | DeepSeek | 只用关键词 |
| 自选 | 自己选供应商和模型（没测过） | 自己选 |
| 全本机（实验） | 本机大模型 | 本机向量 |

本机向量有两种来源：**自带**（Mac 的 M 系列；原委替你准备向量程序和模型，下载前先问你、说清大小，下载后按原委这一版钉住的校验码核对；不用你装别的软件）；或者用你电脑上已有的 LM Studio、Ollama。**测过的只有 LM Studio**：自带程序用的是同一个模型文件，算出的向量和 LM Studio 的几乎一样（核对时全量 11,588 句里有 8 句略低于我们定的线，最低 0.9977，没有低于 0.995 的），但没过我们自己定的严格标准，所以不写「测过」。

也可以让助手来装：把 `docs/让助手来装.md` 交给 Hermes。助手只会先列计划给你看，密钥由你自己在终端里设。

一次查询中，完整向量身份相同的工作区共用问句向量。新配置的查询超时默认 10 秒；旧配置写死的值不会自动改，低于 10 秒时状态会提醒。要调整旧的 5 秒设置，在那个机器人的 `yuanwei.toml` 的 `[embedding]` 下改成 `timeout_query = 10`，然后重启 Hermes。安装采用的 `partial` 模式在超时后仍退回关键词，并登记原因。

完整说明（装、用、看状态、卸载，每一步改什么、怎么撤回）：`docs/装到Hermes上.md`。

## 你说了算

- **这个窗口别用记忆。** 说一句「别用记忆」，或者在消息第一行写 `#yuanwei-nomem`，这个对话窗口就不再查原委的记忆，直到你重新打开。打开要你自己确认：回一句「确认开启」，或者第一行写 `#yuanwei-mem`，助手替你确认不了。在你自己的电脑上和上面列的一对一会话里，提问卡里你打的字和直接发的话一样算：口令或大白话的「关」从下一轮起生效；在 Telegram、Discord、Slack 上，要先点「其他」再打字、或者这道题没有选项，才这样算。点的选项不算。别的会话里在提问卡里打口令不起作用，等卡片结束后直接发一条 `#yuanwei-nomem`。提问卡里的回答永远打不开记忆、也确认不了删除；要开或要删，等卡片结束后直接发一条「确认开启」或「确认删除」。能保证的只有口令；大白话靠助手听懂，可靠度没量过。
- **删掉一段对话。** 跟助手说一声，你整条回复「确认删除」才删；也可以用命令删。原委里这段对话的原话会删掉，跟它有关的整理文字也一起清掉，删了找不回来。在 Hermes 里删对话，原委这边不会跟着删，原话仍能查到，要在原委里另删：最好先在那段对话里让助手删，再去 Hermes 里删；已经删了的，先用 `yuanwei conversations list hermes` 找到编号，再用 `yuanwei conversations delete hermes <编号> --yes` 删。在 Hermes 里重新生成、改一句再发、`/undo` 收回的话，原委照样留着，不标哪份被换掉。
- **对话里的密钥先遮掉。** 写成认得出的样子的密钥和密码（`sk-…`、`XXX_KEY=…`、「密码是 …」、`password=…`），存之前先遮掉，不进记忆，也不发给整理用的模型。认不出的格式可能会漏（比如「密码是」后面跟的是汉字、又没加引号的密码）；前后什么都没有、只打了一个密码的（比如在提问卡里打的），照打的存。
- **存在你自己的电脑上。** 记忆库是本机的一个 SQLite 文件。整理时会把对话发给你配置的模型服务；向量服务默认只连本机。
- **聊天平台只记已登记本人的私聊。** 未登记、其他人和机器人的话不记也不查；这一版所有聊天平台的群聊都不记也不查，包括你本人在群里说的话；已知缺口（待修）：原委按 Hermes 报的聊天类型判断，下面这几种多人聊天里，原委对已登记的本人照常启用：Discord 服务器（Hermes 默认把在频道里 @ 机器人的每条消息挪进一个新帖子，所以服务器里的对话大多算在内；只有回复、关了自动开帖的频道仍不记）、Slack 多人私信、LINE 多人房间、被 Hermes 当成私聊的 Matrix 房间（比如没起名字、标成私聊、却有三个人以上的房间），以及你把自己登记成 `api_server` 本人时、别的机器上的 Hermes 通过 API 发给你机器人的群聊轮次（这样发来的每一轮都当成你的话，不管群里是谁说的）。在这些地方你的话会被记下，助手也能翻你的记忆，回的话那里的人都看得到；私事只在真正的一对一里聊。向导会逐个平台问本人账号，也可以跳过。已经装好的用 `yuanwei owners set <平台> --id <本人编号> --yes` 补登记，重启 Hermes 生效；给某个机器人登记时加 `--hermes-home <它的目录>`。`set` 会替换该平台整份名单，多个本人账号要重复 `--id`。可在与 Hermes 的私聊里发 `/whoami` 查本人编号，别用显示名、机器人的账号，或共用、自动的发送者编号（比如 API 的 `api`、webhook 的路由）；Hermes 的白名单不等于本人登记。
- **每个机器人一个库。** Hermes 里新建的机器人要单独装一次原委（对它的目录跑一次向导）；没装之前，复制来的设置不会启用，也不会读写主 Hermes 的库。
- **项目，包括 Hermes 桌面版。** 原委把对话记进它所在文件夹对应的 Hermes 项目；不在任何项目里的，记进「生活」。Hermes 桌面版不把项目文件夹交给记忆插件（Hermes 上游问题 #144869），所以原委靠 Hermes 的一个内部函数问「这一轮的文件夹」。这不是 Hermes 写进插件接口的约定：Hermes 把它改名、两个来源都不可用的话，桌面版的对话才会退回记进「生活」；等 Hermes 上游修好 #144869，原委就直接用它传来的文件夹。只管本机的桌面版和终端界面；Telegram 等聊天平台不问，仍记进「生活」。本次验证针对普通桌面主对话；`/btw` 这类旁支、辅助会话和整理用的会话不在这个范围内，不承诺统一记进「生活」（`/btw` 的分支，Hermes 自己设了 `skip_memory=True`，原委不记，这是 Hermes 本来的设计）。
- **也可以不整理。** 整理要密钥、要花钱；`yuanwei organize off --yes` 就关掉（`on` 再打开，`status` 看；不加 `--yes` 只列计划；改完重启 Hermes）。关着时原话照常存、照常查，不发请求、不要密钥，查回来的话不挂「未整理」；关着时存下的对话会在打开后按顺序补整理。
- **整理用的密钥全局一份。** 几个机器人共用，换密钥只换一次（`yuanwei key set`）；某个机器人要用别的，可以单独给它设（`yuanwei key set --this-bot-only --hermes-home 它的目录`）。想换全局目录可设 `YUANWEI_KEY_DIR`（只认绝对路径；目录会被设成只有你能读，要用专门放密钥的目录；终端和 Hermes 服务要用同一个设置）。`yuanwei key status` 只报来源，不显示密钥的值。
- **Hermes 自带的记忆照常开着。** 原委只占 Hermes「外接记忆插件」那一个位置。上面那个「别用记忆」的开关只管原委，管不到 Hermes 自带的笔记。

## 测出来怎么样

我们写了一份 150 次对话的中文长故事，出了两批题，每批 55 道。三个记忆系统各自整理，再交给同一个回答模型（DeepSeek）作答，每题的材料额度相同（16,000 词元）。下面是答完整的题数（2026-11-02）：

| 系统 | 第 48 次对话后 | 第 150 次对话后 |
|---|---|---|
| 原委 | 50 | 43 |
| Mem0 | 49 | 43 |
| Hindsight | 47 | 34 |
| 不用记忆系统，把之前的全部原话直接给模型（对照，不受额度限制） | 54 | 没测 |

限制：
- 这一版只管你和某一个机器人的一对一：群聊、机器人之间互发的消息不记也不查（上面说的几处缺口除外）；想记住群里定的事，回到一对一里说一句；
- 11 月 17 日新增的本人登记流程和全部群聊拦截用假环境做过离线检查；微信上，作者自己的安装记对了已登记本人的一对一消息，群聊拦截、挡住未登记的人只在隔离的 Hermes v0.23.2 里用微信适配器（联网换成假的）跑过，没在真的聊天平台上核过。`status hermes`／`doctor hermes` 会提醒漏登记，按平台显示因未登记或不是本人而没记的累计事件数；不回填旧消息，跨重启重送可能重复计数；
- 相关度下限不是「无答案检测」。它只决定哪些原话够格当候选，判断不了你的记忆里到底有没有答案；不相关的问题也可能带回材料（我们自己的小规模构造测试里，留出的 24 条不相关问法有 6 条仍放进了至少一条原话）。这个下限是针对一个向量模型文件（Qwen3-Embedding-0.6B-Q8_0）在 LM Studio 下标定的。没标定的向量模型会退回只看关键词命中，换了说法的问题可能什么也找不到；`yuanwei status hermes` 和 `yuanwei doctor hermes` 会说明这一点（`doctor hermes` 此时退出码为 1）。同一个模型文件，不管用哪个运行程序（包括自带向量程序）都沿用这个门槛；运行程序不在实测名单上的，状态里会注明「当前运行程序未实测」，实际只有 LM Studio 这条路测过（自带程序没有在真机上测过）。升级前建立的旧检索游标会失效，要重新查一次；
- 故事和题是我们自己编的，不是公开测试集；
- 每个系统只跑了一遍；
- 判卷的人知道比的是哪几家，换一位判卷人复判时，第 150 次那批 Mem0 比原委多 4 题；
- 预览版现在的写法，11 月 10 日在同一批题上重答、另一次判卷，是 53 题和 46 题，不和上表直接比。

公开测试集上的成绩、多跑几遍的波动、费用和速度，后续会补。
